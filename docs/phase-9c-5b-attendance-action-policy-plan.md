# Phase 9C-5B: 지각 기준 설정 및 출결 처리 Quick Action 설계

본 문서는 출결관제 화면이 기존 출결관리 화면을 대체하기 위해 필수적으로 요구되는 지각 판정 정책 설정 및 신속한 출결 처리(Quick Action)와 이미 완료된 출결에 대한 수정/보완 정책 설계 문서입니다.

---

## 1. 지각 기준 설정 정책
* **지각 판정 후보**: 태블릿/키오스크 등의 매체를 통해 입력된 실제 등원(출결) 시간이 예정 수업 시간보다 늦을 경우 지각 후보로 자동 등록됩니다.
* **지각 확정 기준**: 학원별로 설정된 '지각 기준 분(Threshold)'을 **초과**한 경우 최종적으로 '지각'으로 판정합니다.
  * *예시*: 예정 수업이 14:00이고 지각 기준 설정이 10분인 경우, 14:10분 등원까지는 정상 '출석'으로 판정하며 14:11분 등원부터는 '지각'으로 판정합니다.
* **기본값 및 설정 범위**:
  * **기본값**: 10분
  * **설정 범위**: 5분 ~ 60분 (5분 단위 조절 가능)

---

## 2. 학원정보관리와 출결관제 역할 분리
지각 기준 설정은 개별 일회성 처리나 관제 수준의 액션이 아닌 **학원 전체의 운영 정책 및 영속 환경설정**에 해당하므로, 역할에 맞게 화면을 엄격히 분리합니다.

* **학원정보관리 화면 (Settings)**
  * **역할**: 지각 기준 분(Threshold)을 지정하고 수정하는 관리 기능 제공.
  * **UI 요소**: '지각 판정 기준 분' 선택을 위한 드롭다운 또는 넘버 셀렉터 (5분 단위, 5분~60분).
  * **데이터 저장**: `stateStore.db.settings` 하위에 `lateThresholdMinutes` 필드로 저장하여 영속화.
* **출결관제 화면 (Attendance Control)**
  * **역할**: 설정된 지각 기준 분을 조회하여 화면 상단 또는 헤더 영역에 정보 표시 및 실제 지각 여부 판정 로직에 연계 적용.
  * **UI 예시**: `"현재 지각 기준: 수업 시작 후 10분"` 문구 노출.
  * **로직**: `getAttendanceWarnings` 등의 출결 Warning 및 등원 시각 자동 판정 로직 호출 시 `stateStore.db.settings.lateThresholdMinutes` 값을 파라미터로 로드하여 판정.

---

## 3. 출결 처리 Quick Action 범위
원생들의 출결을 복잡한 과정 없이 즉시 처리할 수 있도록 직관적인 Quick Action을 지원합니다.
* **결석 처리 간소화**: 결석을 등록할 때 구체적인 불참 사유나 비고(Note)의 입력을 의무화하지 않고, 클릭 한 번으로 빠르고 유연하게 처리할 수 있게 합니다.
* **UI 연계**: 출결관제 테이블 행 내부 또는 우측 액션 버튼(예: `[출석]`, `[지각]`, `[결석]`)을 통해 마우스 클릭 한 번으로 대상 학생의 출결 상태를 즉각 반영하도록 설계합니다.

---

## 4. 이미 처리된 출결 수정 정책
현장 운영 중 발생하는 휴먼 에러나 기기 입력 시간 오차 등을 해결하기 위해, 이미 상태가 확정되어 저장된 출결 데이터도 재수정이 가능해야 합니다.
* **양방향 수정 완벽 지원**:
  * `출석` $\leftrightarrow$ `지각`
  * `출석 / 지각` $\leftrightarrow$ `결석`
  * `결석` $\leftrightarrow$ `출석 / 지각`
* **데이터 일관성 보장**: 변경 시 기존 `stateStore.db.attendance` 내의 해당 매칭 레코드를 업데이트하거나 덮어써서, 화면 갱신 후 KPI 카드 및 집계 지표가 실시간으로 재구성되도록 처리합니다.

---

## 5. 알림톡 / 푸시 연동 보류 정책
* **현재 상태**: 알림 서비스 모듈은 현재 Mock 형태로만 구현되어 있습니다.
* **연동 보류**: 이번 출결 처리 및 수정 구현 과정에서는 실제 알림톡이나 푸시 메시지를 발송하지 않습니다 (실제 외부 API 발송 기능 금지).
* **향후 확장성**: 추후 알림 전송 기능이 정식 런칭되면, 출결 Quick Action 또는 수정 이벤트 발생 시 자동으로 연동 발송될 수 있도록 전송 히스토리 및 발송 상태를 연계할 수 있는 구조적 확장성만 보장합니다.

---

## 6. 추천 구현 순서
1. **[9C-5B-1] 학원정보관리 지각 기준 설정 UI/API**
   * 학원 설정 DB 스키마(`stateStore.db.settings.lateThresholdMinutes`) 생성 및 학원정보관리 뷰 화면에 5분~60분 범위 설정 드롭다운 마크업 추가.
2. **[9C-5B-2] 출결관제 지각 기준 표시 및 판정 로직 연결**
   * 출결관제 화면에 현재 지각 기준 수치 노출 구현. Warning 알고리즘 및 등원 판독 함수에 해당 영속 환경설정 값을 인입하여 지각 판정 기준 동기화.
3. **[9C-5B-3] 출결관제 출석/지각/결석 Quick Action**
   * 테이블 행에 퀵 액션 트리거 바인딩. 결석 처리 시 사유 입력 창 없이 1-Click 즉시 반영되도록 구현.
4. **[9C-5B-4] 출결 수정/덮어쓰기 및 테스트**
   * 기 처리된 출결 상태를 클릭하여 변경할 때 DB 내 기존 레코드를 오버라이트(overwrite) 및 KPI 지표 즉시 리프레시 로직 완료. E2E/Unit 테스트 보강을 통한 정상 통과 검증.

---

## 7. 추가 제안 / 다음 개선 후보
* **지각 기준의 강사별/원생별 차등 적용**: 기본 10분을 유지하되, 특별 관리가 필요한 특정 클래스나 지각이 잦은 일부 원생에게 맞춤형 지각 기준 분을 개별 지정할 수 있는 정책 고도화.
* **결석 철회 이력 로그 생성**: 출결이 번복된 이력(`출석 -> 결석 -> 출석` 등)을 히스토리 로그 테이블에 기록하여, 원장과 강사 간의 출결 처리 분쟁이나 오해 방지.
