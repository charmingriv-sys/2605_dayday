# Phase 8C-5: 오늘 원장 콘솔 실사용 UX 마감 설계 문서

본 문서는 오늘 원장 콘솔이 실제 현장(원장, 행정 실무자)에서 하루 종일 안정적으로 쓰이고 업무 피로감을 줄일 수 있도록 수동 메모/일정의 CRUD 완성, 보류/숨김 업무 필터링, 완료 복원 및 입력 폼 조작 UX 마감 설계 방안을 정의합니다.

---

## 1. 현재 오늘 원장 콘솔 조작 기능 분석

현재 Phase 8C-4A-2까지 완료된 콘솔의 조작 가능 여부를 평가합니다.

| 조작 항목 | 가능 여부 | 현재 구현 방식 / 한계점 |
| :--- | :--- | :--- |
| **수동 운영 메모 추가** | **가능 (OK)** | 좌측 폼 입력 후 추가 클릭 시 큐 및 캘린더 동시 노출. |
| **업무 완료 처리** | **가능 (OK)** | 카드 우측 `[V]` 클릭 시 `done` 처리 및 취소선/회색 보존. |
| **업무 보류 (Snooze)** | **부분 가능** | `[모래시계]` 클릭 시 1시간 보류. 단, 보류된 목록을 따로 볼 수 없음. |
| **업무 숨김 (Dismiss)** | **부분 가능** | `[눈숨김]` 클릭 시 화면에서 즉시 제외. 단, 되살리거나 조회할 방법 없음. |
| **일정 chip / popover** | **부분 가능** | 날짜 셀 클릭 시 일정 팝오버 노출. 팝오버 아이템 클릭 시 좌측 폼에 자동 로드. |
| **추천확인 자동 동기화** | **가능 (OK)** | 미납/출결 지연 건이 보라색 뱃지/칩으로 노출 및 조건 해소 시 완료 보존. |
| **메모/일정 수정 (Edit)** | **불가능** | 등록된 업무의 시간, 구분, 텍스트를 수정할 수 있는 UI/UX 결여. |
| **메모/일정 삭제 (Delete)**| **불가능** | 완료되거나 실수로 생성된 메모를 영구 삭제할 수 없음 (숨김만 가능). |
| **완료 업무 복원 (Re-open)**| **불가능** | 실수로 완료 버튼을 눌렀을 때, 대기 업무로 되돌릴 수 있는 방법이 없음. |

## 2. 실사용성 제고를 위한 UX 개선 후보

콘솔을 TODO 리스트가 아닌 실제 "학원 관리 관제 화면"으로 작동시키기 위한 UX 후보군입니다.

### A. 입력 폼의 추가/수정 모드 통합 UX
* **이슈**: 일정을 수정하는 별도 모달을 띄우는 것은 모바일/태블릿 기기에서 화면을 가려 오조작을 유도합니다.
* **해결**: 일정 chip이나 큐 카드를 클릭했을 때, 좌측 입력 폼에 데이터가 주입되면서 폼 헤더가 `새로운 운영 메모 추가` $\rightarrow$ `운영 메모 수정`으로 전환됩니다.
* **동작**:
  - 폼 하단의 `[추가]` 버튼이 `[수정 완료]` 및 `[수정 취소]` 2개 버튼으로 전환됩니다.
  - 수정 완료 클릭 시 `stateStore.updateTodayTask(id, patch)`를 수행하고 폼을 초기화합니다.
  - 수정 취소 클릭 시 기존 입력값을 지우고 폼을 기본 "추가 모드"로 되돌립니다.

### B. 완료 업무 복원 (Re-open)
* **이슈**: 마우스 오클릭이나 터치 실수로 완료를 눌렀을 때 되돌릴 수 있어야 합니다.
* **해결**: 완료 표시된 회색 카드에 `[되돌리기]` (반시계 화살표 아이콘) 버튼을 제공합니다.
* **동작**: 클릭 시 해당 태스크의 status를 `'open'`으로 전환하고, `completedAt`을 제거하여 대기 업무 큐의 시간순 정렬 위치로 복귀시킵니다.

### C. 메모/일정 영구 삭제 (Delete)
* **이슈**: 불필요하거나 잘못 등록된 임시 메모를 큐에서 완전히 지울 수 있어야 합니다.
* **해결**: 수정 모드 중이거나 큐 카드 우측 액션 영역에 `[삭제]` (쓰레기통 아이콘) 버튼을 배치합니다.
* **동작**: 실수 방지를 위해 `confirm("이 운영 메모를 영구 삭제하시겠습니까?")` 컨펌을 거쳐 `stateStore.deleteTodayTask(id)`를 실행하고 화면을 갱신합니다.

### D. 대기 업무 큐의 필터 탭 (Filter Tabs)
* **이슈**: 숨김(dismissed) 처리한 업무나 보류(snoozed) 상태인 업무를 원장이 확인하고 조치할 수 있어야 합니다.
* **해결**: "운영 대기 업무" 섹션 타이틀 하단에 콤팩트한 탭 필터를 추가합니다.
  - `[대기 업무 (N)]` (기본값: open 및 보류 시간 경과 건)
  - `[완료된 업무 (M)]` (오늘 완료된 done 건)
  - `[숨김/보류 업무 (K)]` (snoozed 대기 중인 건 및 dismissed 처리된 건)
  - `[전체 업무]` (상태 무관 전체 목록)

## 3. 구현 우선순위 및 제약 사항

콘솔 상태 엔진 및 디자인 시스템 일관성을 지키기 위한 우선순위 격리 매트릭스입니다.

* **최우선순위 (MVP 마감 대상)**:
  1. **A. 입력 폼 추가/수정 모드 통합** (메모 수정 CRUD 완료)
  2. **B. 완료 업무 복원 기능** (되돌리기 액션)
  3. **C. 메모 영구 삭제 기능** (컨펌 기반 완전 삭제)
  4. **D. 큐 필터 탭 제공** (숨김/보류 업무 접근성 보장)
* **차선순위 (추후 고도화)**:
  - 캘린더 내 일정 chip 드래그 앤 드롭 이동 (달력 시간 변경)
  - 캘린더 칩 더블클릭 시 상세 팝업창
* **배제/제약 사항 (현재 단계 금지)**:
  - 실제 Google Calendar 연동 (보류 상태 유지)
  - 카테고리 종류 자체를 수정하는 설정 창 (설정 모듈과의 복잡도 증가 방지)

## 4. 상세 구현 로드맵 제안 (작은 Phase 분할)

### Phase 8C-5A: 수동 메모 수정 및 영구 삭제 CRUD 완료
* **목표**: 캘린더 chip / 큐 카드를 클릭하여 좌측 폼을 수정 모드로 전환하는 연동 및 삭제 컨펌 기능을 완성합니다.
* **세부 작업**:
  - `todayConsoleView.js` 내에 수정 모드 상태(`editingTaskId`) 추적 변수 탑재.
  - 카드/칩 클릭 시 `editingTaskId`에 ID 바인딩 및 버튼 상태 토글 (`[수정 완료]`, `[취소]` 노출).
  - 큐 카드에 `[삭제]` (쓰레기통) 아이콘 추가 및 `stateStore.deleteTodayTask` 연동.

### Phase 8C-5B: 완료 복원 및 큐 상태 필터 탭 구현
* **목표**: 완료된 업무의 복원 액션 처리 및 숨김/보류 상태 카드를 필터링하여 볼 수 있는 탭 UI를 구현합니다.
* **세부 작업**:
  - 완료된 카드에 `data-action="reopen"` 버튼 렌더링 및 복원 이벤트 바인딩.
  - 큐 리스트 상단에 `[대기] [완료] [숨김/보류] [전체]` 필터 버튼 바인딩 및 선택 상태에 따른 큐 필터링 렌더링 처리.

### Phase 8C-5C: 모바일 뷰 터치 타겟 보정 및 다이얼로그 팝업 개선
* **목표**: 모바일/태블릿 화면 크기에서 캘린더 칩 및 셀 터치가 용이하도록 패딩 값을 조정하고, 시간 선택 UI 포커스 안정화를 검증합니다.

## 5. 테스트 및 수동 검증 계획

### 자동화 E2E 테스트 (Playwright)
* **수정 흐름 검증**:
  - 특정 메모 카드를 클릭했을 때 좌측 폼 제목이 "운영 메모 수정"으로 바뀌는지 확인.
  - 내용을 수정하고 `[수정 완료]`를 클릭했을 때 큐 카드의 제목과 설명이 변경되는지 검증.
* **삭제 흐름 검증**:
  - `[삭제]` 버튼 클릭 시 `dialog` 핸들러를 사용해 `confirm`을 수락하고, 해당 카드가 목록에서 완전히 소멸하는지 확인.
* **복원 및 필터 검증**:
  - `[되돌리기]` 버튼 클릭 시 완료 목록에서 사라지고 다시 대기 업무 목록의 올바른 시간순으로 복귀하는지 검증.

### 사용자 수동 검증 체크리스트
1. 메모 카드를 클릭했을 때 수정 모드로 안전하게 전환되고, 수정 취소 시 빈 입력 폼으로 원복되는가?
2. 실수로 완료한 업무 카드를 복원했을 때, 완료 뱃지가 사라지고 정상 대기 업무 카드로 복귀하는가?
3. 불필요한 메모를 삭제했을 때, 목록에서 완전히 지워지는가?
4. `[숨김/보류]` 탭을 눌렀을 때 이전에 숨겨두었던 추천확인 업무나 보류 중인 할 일들을 정상적으로 모아볼 수 있는가?
