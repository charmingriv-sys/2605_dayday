# Phase 16Z: 메시징/학부모 포털/Mock SMS 최종 통합 정리 및 체크포인트

본 문서는 Phase 16I부터 Phase 16W까지 구현 및 조율된 학부모 메시징, 원장 메시지 보내기, 오늘 업무 콘솔 Handoff, 학부모 포털 미확인 배지(Unread Badges), Mock SMS Provider 및 메시지 템플릿 정책을 최종 정리하고, 다음 개발 단계를 제시하는 체크포인트 문서입니다.

---

## 1. Phase 16 전체 구현 요약 (Summary of Phase 16)

Phase 16에서는 원장과 학부모 간의 소통 채널 구축 및 모의 발송 시스템의 무결성을 증명하기 위한 다각도의 기능 통합이 이루어졌습니다.
* **원장 영역**: 수신자 지정, 대표 발신번호 선택, 본문 작성 및 모의 발송이 유기적으로 연결된 3열 구조의 메시지 발송 폼 구축.
* **학부모 영역**: 공지사항, 설문조사, 안내사항의 3가지 핵심 소통 탭을 제공하며 읽음 상태에 따른 배지 카운트 제어.
* **인프라 영역**: 실제 외부 API 호출 없이 전송 상태 기록 및 데이터 적재를 수행하는 Mock SMS Provider 설계 및 이중 제출(Double Submit) 방어 구현.

---

## 2. 원장 메시지 보내기 현재 기능 (Director Message Sender)

* **3단 레이아웃 메시지 작성 폼**:
  * **1열 (수신자 선택)**: 원생 목록 검색, 반 필터링, 수신자 유형(본인 / 보호자1 / 보호자2) 토글 선택, 수신 대상 개별 추가/삭제 및 보호자 연락처 유무 표시.
  * **2열 (본문 작성)**: 메시지 종류 선택(LMS/SMS/MMS), 바이트 계산기(90Byte 기준 SMS/LMS 자동 변환), 제목/본문 편집, 수신자별 치환 결과 미리보기(Preview) 지원.
  * **3열 (보관함 및 이력)**: 추천 템플릿, 원장 저장 템플릿 후보군, 최근 발송 메시지 이력, 개별 수신자별 발송 현황(전송 결과) 목록 스크롤 제공.
* **시각 동기화 및 동시성 방어**:
  * 수신인 상단 토글 버튼("본인 / 보호자1 / 보호자2")과 개별 수신 원생 리스트 내의 체크박스 선택 상태가 실시간 부분 렌더링 상황에서도 상호 동기화됩니다.
  * **최종 발송 가드 플래그 (`isSending`)**: "최종 발송" 버튼 클릭 즉시 동기식 가드가 적용되어 버튼을 비활성화하고 `발송 처리 중...` 상태로 피드백을 제공하여 더블 클릭 및 다중 입력에 의한 발송 중복(Double Submit)을 UI 레벨에서 차단합니다.

---

## 3. 학부모 포털 현재 기능 (Parent Portal)

* **알림 및 설문 허브**:
  * 학원 설정(`parentCommunicationTabSettings`)에 따라 공지사항 / 설문조사 / 안내사항 중 활성화(ON)된 탭만 메뉴 및 알림 목록에 동적으로 렌더링됩니다.
  * 비활성(OFF) 처리된 탭은 학부모 화면에서 완전히 숨겨져 노출되지 않도록 가드가 작동합니다.
* **소통 전용 탭 순서의 유지**:
  * 학부모 화면에서는 항상 **공지사항 ➡️ 설문조사 ➡️ 안내사항** 순서로 고정 렌더링을 유지하여 일관성 있는 UX를 제공합니다.

---

## 4. Mock SMS Provider 현재 범위 (Mock SMS Infrastructure)

* **메타데이터 저장 및 멱등성(Idempotency) 방어**:
  * 동일 발송 주기 내 중복 전송을 차단하기 위해 `idempotencyKey`(요청ID + 전화번호 해시 + 채널 + 본문 해시 조합)를 생성합니다.
  * 추후 재시도 메커니즘을 지원하기 위해 `retryOfDeliveryId`(원본 메시지 추적), `retryAttempt`(재시도 횟수), `retryable`(재시도 가능 여부), `retryPolicyReason` 메타데이터를 delivery 구조체 내에 적재합니다.
  * 발송 요청 시 수신인별 전달 로그(`outboundMessageLogs`)와 세부 전송 결과(`outboundMessageDeliveries`) 데이터 구조체를 분리하여 로컬 모의 적재 방식으로 동작합니다.

---

## 5. 실제 SMS/알림톡/Push 미연동 범위 (Out of Scope)

* **외부 통신 API 미연동**: SKT/KT/LGU+ 망 통신사 연동, 외부 대행사(Aligo, Solapi 등) HTTP REST API 연동 로직은 일체 포함하지 않으며, 로컬 메모리 기반 Mock 인프라로만 발송 상태를 시뮬레이션 및 적재합니다.
* **알림톡 정식 심사**: 카카오 비즈니스 채널 인증, 알림톡 승인 템플릿 등록 및 검수 자동화 기능은 포함되어 있지 않습니다.
* **디바이스 OS Push**: iOS/Android 디바이스 토큰 관리, APNS/FCM 푸시 서버 발송 로직은 포함하지 않습니다.

## 6. 템플릿 정책 요약 (Template Policy)

* **시스템 기본 템플릿**: 결석 확인, 상담 안내, 수강료/교재비 납부 등 9가지 핵심 상황별 초안 서식을 내장하여 상단 콤보박스(select)를 통해 대입할 수 있습니다.
* **원장 저장 템플릿 (Custom)**: 원장이 작성 창의 문구를 저장하여 재사용할 수 있으며, 향후 **학원 단위(academyId) 공유 템플릿을 우선 후보군으로 제안**해 협업 구조를 지향하는 설계를 적용했습니다.
* **충돌UX 및 오버라이트 가드 (후속 제안)**: 작성창에 텍스트가 존재할 경우 덮어쓰기 여부를 묻는 Confirm 창을 띄워 데이터 유실을 보완하는 방향을 제안합니다.

---

## 7. 오늘 원장 콘솔 Handoff 정책 (Console Handoff Precedence)

* 오늘 원장 콘솔(미결석 발생, 미납자 목록)에서 특정 액션을 통해 메시지 작성 화면으로 이동할 경우, 해당 업무의 **Handoff 파라미터가 작성 양식을 결정하는 최우선 순위**를 갖습니다.
* **자동 세팅 규칙**: 작성 영역이 완전히 비어 있는 경우(제목/본문 공란)에만 Handoff 추천 기본 템플릿을 자동 주입합니다. 만약 작성 중인 기존 텍스트가 존재하면 사용자 데이터 보존을 위해 자동 대입을 스킵하고 배너를 통해 수동 클릭 기회를 줍니다.

---

## 8. Unread/Badge/Read 처리 정책 (Unread Status & Badges)

* **사이드바 메뉴 배지 계산**:
  * 학부모 포털 좌측 사이드바의 "알림 및 설문" 아이콘 옆 배지 숫자는 활성화(ON)된 소통 카테고리의 읽지 않은 개수(안내사항 미확인 수 + 미참여 설문 수 + 미확인 공지 수)만 합산하여 표시합니다.
  * **설정에서 비활성화(OFF)된 소통 탭의 미확인 항목 수치는 전체 배지 카운트 합산에서 즉시 제외**됩니다.
* **개별 읽음 상태 처리**:
  * 공지사항 및 설문조사는 사용자가 상세 내용을 클릭하는 순간 읽음 상태(`readAnnouncementIds`, `readSurveyIds` 추가)로 전환되며 배지가 감소합니다.
  * 시스템 자동 알림(`parentMessages`)은 출결 현황이나 수강료 청구 상세와 매핑되어 동작하며, 수동 소통 채널 데이터와 무관하게 분리 관리됩니다.

---

## 9. 개인정보 비노출/마스킹 정책 (Privacy & PII Masking)

* **개인정보 비노출 원칙**:
  * UI 화면(최종 발송 탭, 발송 현황 결과 탭 등) 및 DB 저장 객체 내에 수신인 보호자의 **원문 전화번호(raw phone) 및 변환 번호(normalizedPhone)를 평문으로 직접 적재하거나 노출하지 않습니다**.
* **안전한 해싱 및 마스킹 적용**:
  * 중복 체크를 위한 멱등성 키(`idempotencyKey`) 생성 시, 평문 번호 대신 **안전하게 해싱된 `phoneHash`**를 사용합니다.
  * UI 상에 번호를 식별용으로 표기할 때는 뒷자리 및 중간을 암호 별표 처리한 **`maskedPhone` (예: `010-****-1234`)** 형태만을 노출하여 개인정보보호 규정을 준수합니다.

## 10. 아직 보류된 항목 (Pending Items)

다음 기능들은 설계 및 목업 수준의 가이드라인으로 구상되었으며, 실제 백엔드/데이터베이스 연동 전 단계로 현재 구현에서 **미구현 및 보류 상태**로 설정되어 있습니다.
1. **실제 SMS/알림톡 API 게이트웨이 연동**: 국내 이동통신사 망 및 알리고/솔라피 API 연계 처리
2. **Push 알림 및 앱 설치 상태 표현**: 디바이스 백그라운드 푸시 알림 및 모바일 앱 설치 여부 추적
3. **PG/VAN 결제 연동**: 카카오페이, 토스페이, 이니시스 등 PG사 모바일 결제 및 카드 수납 승인 연계
4. **서버 연동 및 간편 로그인 (OAuth)**: JWT/OAuth2 기반 카카오/네이버 소셜 간편 로그인 및 영속 DB 연동
5. **휴원/퇴원 상태 처리**: 휴원생 및 퇴원생 상태에 따른 이력 조회 제한 및 스케줄 자동 삭제 정책
6. **통합 대시보드 통계**: 수강료 미납률 추이, 출결 워닝 점수 분포 등 시각 차트 모듈 연계
7. **권한별 사이드바/페이지 접근 감사**: 원장/교사/학부모 간 비인가 라우트 접근을 제한하기 위한 보안 미들웨어 구현
