# Phase 8C-3: 오늘 원장 콘솔 빠른 운영메모 UX 및 캘린더 병렬 레이아웃 설계안

본 문서는 오늘 원장 콘솔의 수동 할 일 추가 UI를 빠른 운영메모 중심 UX로 재설계하고, 하단에서 운영대기업무와 캘린더를 동시에 병렬로 모니터링하기 위한 설계 세부 사항을 정의합니다.

---

## 1. 현재 Phase 8C-2 UI의 한계
* **텍스트 분리의 불편함**: 수동 메모 등록 시 제목과 설명을 따로 폼 필드로 채워야 하여 신속한 기록과 처리가 생명인 매장 현장 환경에서 입력 피로가 큽니다.
* **시간 입력의 제약**: 단일 마감 시각(`dueAt`) 필드만 존재하고 `datetime-local` 표준 인풋에 의존하여, "14:00 ~ 15:00 상담 예약"처럼 기간을 지닌 일정성 메모를 표현하기 어렵습니다.
* **우선순위 개념의 모호성**: 일반적인 원장의 하루 메모는 위계적 '우선순위(urgent/today/info 등)'보다 직관적인 업무 '구분(메모, 상담예약, 확인필요)'으로 대분류하는 것이 실질적 운영에 더 자연스럽습니다.
* **업무 흐름과 캘린더의 단절**: 할 일 목록만 세로 큐로 길게 나열될 뿐, 학원 전체 및 Google Calendar 상의 시간 약속과 병렬로 겹쳐서 확인하기 어렵습니다.
* **완료 즉시 소멸로 인한 피드백 유실**: 완료 클릭 시 큐에서 즉시 사라져, 원장이 "오늘 하루 동안 무엇을 완료 처리했는지" 퇴근 전에 리뷰하거나 확인하는 데 어려움이 있습니다.

## 2. Phase 8C-3 MVP 범위 및 제외 범위

### MVP 범위
* **단일 텍스트 입력창 (Textarea)**: 제목/설명 구분 없이 하나의 큰 입력란에 빠른 메모 작성.
* **"구분" 필드 도입**: 기존의 priority를 `category` 성격의 구분자로 대체 (기본값: 메모, 상담예약, 확인필요).
* **시작/종료 시각 구조**: 일정의 지속 시간(Start/End)을 설정할 수 있는 시간 모델 정립.
* **완료 항목 시각 표시 유지**: 완료 처리 시 큐에서 제거되는 대신 취소선, 회색톤 및 불투명도 조절을 적용해 화면에 보존.
* **병렬 레이아웃 구성**: 좌측 '운영 대기 업무 큐', 우측 '일일 일정 캘린더' 스켈레톤 및 병렬 투영.
* **로컬 캘린더 데이터(App Calendar) 바인딩**: `mockCalendarEvents` 데이터를 시간 흐름에 맞춰 우측 캘린더 영역에 렌더링.

### 제외 범위
* **실제 Google Calendar API 양방향 동기화**: 본 설계의 범주에서는 Mock 데이터를 다루며, Google OAuth 및 실제 API 연동은 **Phase 8D**로 온전히 격리합니다.
* **구분자 CRUD 설정 UI의 완전 구현**: 구분 추가/삭제 설정 화면은 MVP 릴리즈 이후로 지연하며, MVP 단계에서는 공통 기본 설정을 우선 적용합니다.

## 3. 빠른 메모 입력 UX 제안
* **단일 입력란 (Textarea)**:
  * 모바일 및 데스크톱에서 빠르게 메모를 타이핑하고 전송할 수 있도록 가로지르는 크기의 단일 Textarea 영역을 할당합니다.
  * 메모 작성 시 첫 줄은 `title`로 추출(또는 적절한 길이로 슬라이싱)하고, 줄바꿈 이후의 전체 텍스트는 `description`으로 자동 분리하여 기존 `TodayTask` DB 스키마와 100% 호환되게 처리합니다.
  * placeholder 예시: `"오늘 메모할 내용을 입력하세요. 첫 줄은 제목이 되고 다음 줄부터는 설명이 됩니다."`

---

## 4. "구분" 필드 데이터 구조 제안
* 기존의 `priority` 필드 매핑 구조를 유지하거나, `category` 확장 메타데이터를 활용합니다. MVP 데이터 호환성을 극대화하기 위해 다음과 같이 맵핑합니다:
  * **메모 (`memo` / `info` 대응)**: 일반 메모 업무.
  * **상담예약 (`consult` / `urgent` 대응)**: 학부모/학생 방문 등 시간 약속 일정.
  * **확인필요 (`check` / `today` 또는 `closing` 대응)**: 수납, 출결 지연 확인 등 시스템 연동 경보.

```typescript
// TodayTask 스키마 내 category 필드 확장안
interface TodayTask {
    // ... 기존 필드
    category: 'memo' | 'consult' | 'check' | string; // 커스텀 구분 지원용 문자열 타입 허용
    startAt?: string; // 일정 시작 시간 (ISO 8601)
    endAt?: string;   // 일정 종료 시간 (ISO 8601)
}
```

## 5. 구분 추가/삭제 기능의 MVP/후순위 분리
* **MVP 단계**:
  * `stateStore` 디폴트 세팅에 공통 사용되는 3대 구분자(`['메모', '상담예약', '확인필요']`)를 상수로 주입하여 고정 제공합니다.
* **후순위 단계 (Post-MVP)**:
  * 학원 정보 및 개인 설정 메뉴 하위에 `todayTaskCategories: string[]` 컬렉션을 신설합니다.
  * 원장이 직접 카테고리를 추가(`push`)하거나 삭제(`filter`)할 수 있는 UI를 제공하며, `todayConsoleView` 렌더링 시 이 동적 배열을 읽어와 Select Option을 생성하도록 고도화합니다.

---

## 6. 시작시간/종료시간 입력 UX 제안
* **시작시간/종료시간 인풋**:
  * `datetime-local` 또는 콤보박스 인터페이스를 제공합니다.
  * 시작시간 인풋 값의 변화를 감지하는 `change` 리스너를 바인딩하여, **시작시간을 선택하면 종료시간 필드가 자동으로 시작시간 + 1시간 뒤로 계산되어 동기화**되도록 유도하여 터치를 최소화합니다.
* **시간 입력 편의성 (구글 캘린더 방식)**:
  * 오전/오후 선택 라디오/버튼, 1~12시 시간 셀렉트, 5분 단위(또는 10분 단위) 분 셀렉트로 분할된 UI 컴포넌트를 설계하여 모바일 터치 오조작을 최소화합니다.

## 7. 운영대기업무 + 캘린더 병렬 레이아웃 제안
* **화면 분할 구조 (CSS Grid / Flex)**:
  * 화면 하단 영역을 1:1 또는 1.2:0.8 비율의 2열 그리드로 나눕니다:
    * **좌측 열 (업무 큐 패널)**: 오늘 처리해야 하는 대기/처리 업무 목록 (Done/Snooze/Dismiss 버튼 탑재).
    * **우측 열 (일간 타인라인 패널)**: 09:00 ~ 22:00 시간 슬롯이 1시간/30분 단위로 세로로 나열된 일간 캘린더 뷰.
  * **캘린더 투영**: 
    * `TodayTask` 중에서 시작/종료 시간이 정의된 항목(상담예약 등) 및 `mockCalendarEvents`를 읽어와 우측 캘린더 시간 슬롯 내에 절대 좌표(`top`, `height` 퍼센트 계산)로 시각화 배치합니다.

## 8. APP 캘린더와 Google Calendar Provider 확장 구조
* **동적 캘린더 이벤트 머지 파이프라인**:
  * 캘린더 영역에 일정을 표시할 때, 자체 스토어 일정(`TodayTask`)과 외부 캘린더 일정을 하나의 파이프라인으로 모읍니다.
  * `mockCalendarEvents` 스키마 규격을 구글 캘린더 리소스 응답 데이터 구조와 완전히 통일합니다.
  * **인터페이스 설계**:
    ```javascript
    class CalendarProvider {
        async fetchEvents(dateRange) { /* 구현체에서 재정의 */ }
    }
    class MockLocalCalendarProvider extends CalendarProvider { ... }
    class GoogleCalendarProvider extends CalendarProvider { ... }
    ```
  * 로딩 시 활성화된 provider를 통해 이벤트를 수신한 뒤, 화면 상에서는 출처 구분용 배지(App / Google)만 다르게 부착하여 동일한 타임라인 카드 컴포넌트로 렌더링합니다.

## 9. 완료/보류/숨김 상태 표시 정책 재정의
* **완료 (Done) 상태**:
  * 리스트에서 지워지지 않고 유지됩니다.
  * 디자인 변경 요소:
    * 텍스트 전체에 `text-decoration: line-through;` (취소선) 적용.
    * 투명도 `opacity: 0.5` 및 배경 회색톤 필터링.
    * 완료 버튼을 숨기거나 "완료됨" 플랫 상태 텍스트로 치환.
* **보류 (Snoozed) 상태**:
  * 현재 시각 기준 `snoozedUntil > now`인 동안은 큐 및 캘린더 표시에서 완전히 숨깁니다.
  * 설정 시각 경과 시 다시 `open` 업무와 동일한 명도로 active queue에 노출됩니다.
* **숨김 (Dismissed) 상태**:
  * 화면에서 영구히 제거(필터링) 처리됩니다. 히스토리 감사 로그에서만 추적 가능합니다.

## 10. 구현 Phase 분할안

### [Phase 8C-3A] 빠른 메모 입력 UX 및 시간 자동 동기화 구현
* **내용**: 폼의 입력 요소를 `textarea` 단일 창으로 전송받아 첫 줄을 타이틀로 변환하는 파싱 로직을 추가하고, 시작시간 변경 시 종료시간이 자동 세팅되는 시간 연동 로직을 구축합니다.

### [Phase 8C-3B] 완료 업무 보존 렌더링 및 스타일 시트 적용
* **내용**: 완료 상태의 태스크를 active list에서 필터 제외하지 않고 포함하도록 selector 및 뷰 렌더러를 보완하고, 취소선/투명도 50%의 시각 피드백 CSS를 입힙니다.

### [Phase 8C-3C] 업무/캘린더 2열 병렬 레이아웃 뼈대 수립
* **내용**: CSS Flex/Grid를 활용하여 뷰 영역을 좌측(할 일 목록), 우측(시간대별 캘린더 타임라인 스켈레톤)으로 분할하는 반응형 레이아웃 뼈대를 구현합니다.

### [Phase 8C-3D] Mock 기반 캘린더 일정 맵핑 및 투영
* **내용**: `mockCalendarEvents` 데이터를 로딩하여 우측 타임라인 슬롯 내에 위치 연산을 수행해 카드로 얹어주는 로컬 캘린더 매퍼를 완결합니다.

### [Phase 8D] Google Calendar OAuth 및 읽기 연동 본격화
* **내용**: 구글 API 클라이언트를 연동하여 Mock 어댑터가 아닌 실 서버 구글 캘린더 조회 데이터를 어댑터 파이프라인에 병합하여 캘린더 상에 오버레이 출력을 완료합니다.
