# Phase 13 릴리즈 노트: 오늘 원장 콘솔 및 운영 검수 체크리스트

본 문서는 Phase 13(A~I)에 걸쳐 구현된 **오늘 원장 콘솔(Today Director Console)**의 전체 기능 정의, 정책, 자동점검 기준, 수동 검수 가이드라인 및 향후 백로그를 정리한 릴리즈 고정 문서입니다.

---

## 1. 오늘 원장 콘솔의 역할 정의

### 대시보드와 오늘 원장 콘솔의 기능적 구분
* **기존 대시보드**: 학원 운영 전반에 대한 통계 정보, 누적 수치, 시각화된 차트 등을 제공하여 중장기적인 의사결정과 전반적인 현황 모니터링을 목적으로 합니다.
* **오늘 원장 콘솔**: 당일 원장이 즉시 확인하고 직접 액션을 취해야 하는 일일 운영 태스크에 집중합니다. 

### 오늘 원장 콘솔의 핵심 정의
* 오늘 원장 콘솔은 **"오늘 원장이 확인 및 해결해야 할 업무를 자동점검 / 직접등록 / 상담예약 기준으로 취합하여 일괄 관리하는 일일 운영 큐(Queue)"**로 정의됩니다.
* 개별 상세 도메인 기능(출결 상세, 수납 내역, 주요일정 상세 등)은 기존 메뉴에서 더 깊게 확인 및 편집할 수 있으나, **오늘 콘솔에서는 당일에 조치해야 할 항목들만 요약 및 큐화하여 단일 창구에서 신속하게 처리**할 수 있도록 하는 것이 핵심 원칙입니다.

## 2. 상단 9개 KPI 카드 목록 및 세부 기준

상단에 배치되는 9개 KPI 카드는 가로 배치되며, 모바일 등 반응형 레이아웃에서는 지정된 순서대로 정렬됩니다. **모든 카드의 카운트는 "고유 원생/강사 수"가 아닌 "운영 대기 업무 큐에 표시된 개별 업무(Row) 건수"를 기준**으로 집계됩니다.

| 순서 | KPI 카드명 | 카운트 기준 | 하단 큐 필터링 기준 | 관련 도메인 데이터 | 자동/수동 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | **운영메모** | 미완료 상태의 수동 등록 운영메모 건수 | `category = 'memo'` 이고 상태가 대기(`open`)인 태스크 | TodayTask (수동) | 수동 |
| 2 | **결석 확인** | 당일 결석 처리 후 원장의 확인이 안 된 건수 | `category = 'attendance'` 중 결석 관련 미완료 태스크 | Attendance (자동) | 자동 |
| 3 | **특이출결** | 당일 출결 중 지각, 하원누락 등 보정 필요 건수 | `category = 'attendance'` 중 지각/누락 미완료 태스크 | Attendance (자동) | 자동 |
| 4 | **특이근태** | 당일 강사 근태 중 지각, 미출근, 퇴근누락 건수 | `category = 'staff_attendance'` 미완료 태스크 | StaffAttendance (자동) | 자동 |
| 5 | **수납확인** | 당일 발생한 완납/수납 처리 내역 확인 건수 | `category = 'billing'` 중 수납완료(`paid`) 미완료 태스크 | Payment (자동) | 자동 |
| 6 | **미수납 확인** | 납부일이 도래했으나 미납 상태인 원생 수강료 건수 | `category = 'billing'` 중 미납(`unpaid`) 미완료 태스크 | Payment (자동) | 자동 |
| 7 | **일정확인** | D-3 ~ D-day 범위에 도래한 주요 일정 건수 | `category = 'schedule'` 중 미완료 태스크 | MajorSchedule (자동) | 자동 |
| 8 | **교재 확인** | 강사로부터 요청된 교재 지급 승인 대기 건수 | `category = 'book_check'` 미완료 태스크 | StudentBook (자동/수동) | 자동 |
| 9 | **교재 결제 확인** | 수강료와 별도로 청구된 교재비 수납 확인 건수 | `category = 'book_payment'` 미완료 태스크 | Payment (교재비) | 자동 |

## 3. 운영 대기 업무 큐 정책

하단 운영 대기 업무 큐는 수집된 모든 일일 태스크를 상태별로 조회하고 액션을 수행하는 인터페이스입니다.

### 태그 구조 (2줄 배치)
* **1줄 (대분류 - 소스 배지):** `자동점검` / `직접등록` / `상담예약`
* **2줄 (소분류 - 도메인 배지):** `메모` / `출결` / `근태` / `수납` / `미수납` / `주요일정` / `교재` / `교재결제` / `상담`

### 상태 탭 필터링
* **대기**: 현재 미해결 상태인 당일 활성 태스크 목록을 표시합니다.
* **완료**: 오늘 완료 처리된 태스크 목록을 보여주며, 취소선과 완료 시각 정보가 함께 렌더링됩니다.
* **제외/보류**: 원장에 의해 오늘 보류되었거나 큐에서 제외된 태스크 목록을 보여줍니다.
* **전체**: 상태와 관계없이 큐에 적재된 모든 당일 태스크를 모아 보여줍니다.

### 액션 버튼 기능 및 의미
* **완료 (`done`)**: 실제 확인이나 관련 조치가 모두 완료되어 오늘 큐에서 해결 상태로 전환합니다.
* **보류 (`snooze`)**: 당장 처리하기 곤란하여 나중에 다시 확인할 업무로 표시합니다 (기본 1시간 보류).
* **제외 (`dismiss`)**: 오늘 큐에서 태스크를 강제로 감춥니다.
  * **제외 시 확인창(Confirm) 문구:**
    > "이 업무를 오늘 큐에서 제외할까요?
    > 같은 조건의 자동 업무는 다시 표시되지 않을 수 있습니다."

## 4. 자동점검 카테고리별 발생 및 판단 기준

### 원생 출결 (`attendance`)
* **결석 확인**: 당일 수업 시간표 기준 출석 입력이 마감되었으나 `결석` 상태로 남은 원생이 존재할 때 발생합니다.
* **지각**: 출석 시각이 수업 시작 예정 시각보다 늦은 경우에 생성됩니다.
* **하원누락**: 수업 종료 시각이 지났음에도 하원 카드가 태그되지 않았을 때 생성됩니다.
* **지각 + 하원누락**: 지각한 원생이 수업 종료 후 하원 처리까지 누락한 경우 단일 복합 카드로 발생합니다.
* **상태 전이**: 수업 종료 전까지는 `지각` 상태였더라도, 수업이 종료되고 하원 누락 기준을 만족하면 내부 검사를 거쳐 `지각 + 하원누락`으로 상태가 전이됩니다.
* **하원누락 판단 시각 기준**: `실제 출석시각(지각 시) 또는 수업 시작시각` + `기본 수업시간` + `학원 설정 하원누락 유예시간`

### 강사 근태 (`staff_attendance`)
* **강사 지각**: 출근 예정 시각보다 늦게 출근 체크를 한 경우 생성됩니다.
* **강사 미출근**: 출근 예정 시각 + 설정된 미출근 유예시간이 지났음에도 출근 기록이 없는 경우 생성됩니다.
* **강사 퇴근누락**: 퇴근 예정 시각 + 설정된 퇴근누락 유예시간이 지났음에도 퇴근 기록이 없는 경우 생성됩니다.
* **강사 지각 + 퇴근누락**: 지각 출근한 강사가 퇴근 체크까지 누락한 경우 생성됩니다.
* **상호 배타성 및 전이**: `강사 지각`과 `강사 미출근`은 상호 배타적입니다. 미출근으로 판단되어 큐에 노출되었더라도, 강사가 늦게 출근 체크를 수행하면 `강사 지각` 태스크로 실시간 자동 갱신 및 전이됩니다.

### 수납 및 미수납 (`billing`)
* **수납확인**: 원생의 당월 수강료(type=education) 수납 상태가 완납(`paid`)으로 변경될 때 실시간 생성됩니다.
* **미수납 확인**: 납부 기한이 도래했으나 아직 수납 상태가 미납(`unpaid`)인 경우 생성됩니다.
* **구분 기준**:
  * 수강료 관련 데이터만 본 카테고리에 할당됩니다.
  * 교재비(type=book) 수납은 독자적인 '교재 결제 확인' 흐름으로 분리되어 처리됩니다.
  * 미수납 확인에는 과거 월에 누적된 미납 금액도 포함하여 반영합니다.

### 교재 (`book_check` / `book_payment`)
* **교재 확인 (`book_check`)**: 강사 권한으로 원생에게 특정 교재를 지급해 달라는 요청을 생성하면 발생합니다.
  * 원장이 오늘 콘솔에서 **[교재 확인]** 승인 버튼을 클릭하면, `studentBook` 기록이 지급 상태로 변경되며 연관 수강생 `payment` 레코드(교재비 청구)가 자동 생성됩니다.
* **교재 결제 확인 (`book_payment`)**: 교재 확인 승인에 따라 생성된 교재비(type=book) 수납 건이 완납(`paid`)되었는지 모니터링하기 위해 발생합니다.
* **알림톡 정책**: 카카오 알림톡 전송 연동 기능은 현재 미구현 상태이며, 향후 별도 Phase로 연동할 백로그로 분류되어 있습니다.

### 주요일정 (`schedule`)
* **접수마감 기준**: 마일스톤 중 접수마감일(`dueDate`)이 D-3 ~ D-day 이내로 도래할 때 발생합니다.
* **진행/종료 기준**: 행사/일정의 진행 및 종료일(`eventDate` 또는 `endDate`)이 D-3 ~ D-day 이내로 도래할 때 발생합니다.
* **표시 정책**:
  * D-3부터 D-day(당일)까지 오늘 콘솔 큐에 상주 노출됩니다.
  * 동일한 일정일지라도 `접수마감`과 `진행/종료` 마일스톤이 각각 임박하면 서로 다른 독립된 row(태스크)로 생성되어 모니터링 편의를 도모합니다.
  * 시작일(`startDate`)은 현재 일정확인 태스크의 독립 트리거 기준에서 제외되어 있습니다.

## 5. 수동 등록 업무 (직접등록 및 상담예약)

* **운영메모 (`memo`)**: 원장이 오늘 콘솔 상단의 입력 폼을 통해 제목과 상세 내용을 직접 작성하고 분류를 '운영메모'로 선택하여 등록한 업무입니다.
* **상담예약 (`consult`)**: 상담 도메인이나 등록 폼을 통해 예약 시각 기반으로 등록된 태스크입니다.
* **오늘 콘솔 표시**: 직접등록 업무는 우측에 기한(dueAt) 또는 시간 범위(startAt ~ endAt)가 표시되며 큐 목록에 우선 정렬되어 렌더링됩니다.
* **달력 연동**: 수동 태스크 중 시간 정보가 포함된 태스크는 오른쪽의 '오늘 일정 캘린더 월간 그리드'에 칩 형태로 실시간 동기화되어 표시됩니다.
* **정렬 로직**: 큐 내에서 `시작 시각(startAt) -> 마감 시각(dueAt) -> 생성 시각(createdAt)` 우선순위의 오름차순 정책으로 정렬됩니다.

## 6. 설정값 및 관리 화면 연동 정책

원장은 **학원정보관리 > 자동 워닝 설정** 메뉴를 통해 각 자동점검 트리거의 판단 임계치를 설정할 수 있습니다.

* **설정 대상 항목**:
  * 원생 지각 유예 시간
  * 원생 결석 판단 기준 시간
  * 원생 하원누락 유예 시간
  * 강사 지각 유예 시간
  * 강사 미출근 판단 유예 시간
  * 강사 퇴근누락 유예 시간
* **시간 단위**: `0분`부터 `90분`까지 `5분` 단위로 드롭다운을 통해 세밀한 설정이 가능합니다.
* **특수 값 정의**:
  * **사용 안 함**: 해당 자동점검 로직을 완전히 끕니다 (큐에 경고가 생성되지 않음).
  * **00분**: 지각이나 누락 기준 시각과 일치하는 즉시(지연 없이) 경고를 실시간으로 발생시킵니다.

## 7. QA 및 수동 검수 가이드라인

### Warning Seed 도구 사용법
테스트 및 수동 검수를 위해 로컬 스토리지 플래그를 통해 데모 데이터를 세팅할 수 있는 디버깅 유틸리티가 제공됩니다.

1. 브라우저 개발자 도구(F12) 콘솔을 엽니다.
2. 아래 플래그를 설정하여 디버깅 도구를 활성화합니다:
   ```javascript
   localStorage.setItem('DAYDAY_DEBUG_WARNING_SEED', 'enabled');
   ```
3. 페이지를 새로고침하면 화면 우측 상단에 Warning Seed 위젯이 나타납니다.
4. **[Seed Warning Demo Data]** 버튼을 클릭하여 모든 지각, 결석, 미출근, 교재 요청 등 복합 상황 시나리오 데이터를 즉시 주입합니다.
5. 검수 작업을 마친 후에는 반드시 **[Clear Warning Demo Data]**를 클릭하여 모의 데이터를 완전히 청소합니다.
6. 로컬 스토리지 플래그를 삭제합니다:
   ```javascript
   localStorage.removeItem('DAYDAY_DEBUG_WARNING_SEED');
   ```

### 실제 수동 검수 체크리스트
* [ ] **KPI 카드 정렬 및 레이아웃**: 상단에 9개의 KPI 카드가 정의된 순서(운영메모 ~ 교재 결제 확인)로 정상 노출되는지 확인하고, 브라우저 창 크기를 줄였을 때 5열/4열 반응형 그리드로 겹침 없이 유연하게 배치되는지 점검합니다.
* [ ] **큐 태그 2줄 표시**: 각 카드 내 좌측 배지 영역에 1줄(분류), 2줄(도메인) 형태로 태그 텍스트가 줄바꿈되어 깔끔하게 표현되는지 확인합니다.
