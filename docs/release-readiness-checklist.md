# DayDay 배포 준비 상태 체크리스트 (Phase 6G 베이스라인 고정)

본 문서는 DayDay 서비스의 Preview/Production 배포를 실행하기 직전에 개발자와 릴리즈 담당자가 데이터 무결성과 시스템 보안을 최종 확인하기 위한 체크리스트입니다. Phase 6G 기준선의 설계 정합성 검증 지표를 추가 포함합니다.

---

## 1. 배포 전 Git & 보안 확인 사항

배포 파이프라인 작동 전에 터미널에서 다음 점검 단계를 무조건 실행합니다.

### 1.1 Git 상태 확인
- [ ] 정본 작업 폴더(`C:\Users\charm\OneDrive\문서\2605_dayday`)인지 확인.
- [ ] `git status --short` 실행 결과 작업 외 다른 백업 파일(`.backup`, `.bak`, `.old`)이 검출되지 않는지 확인.
- [ ] `git remote -v` 실행 결과 저장소 주소에 개인 토큰(`ghp_...`) 정보가 포함되지 않았는지 점검.

### 1.2 민감정보 노출 스캔 실행
터미널에서 아래 PowerShell 스크립트를 최종 실행하여 검출물이 없는지 확증합니다.
- [ ] 스캔 실행:
  ```powershell
  Get-ChildItem -Recurse -File |
    Where-Object {
      $_.FullName -notmatch "\\.git\\" -and
      $_.FullName -notmatch "\\node_modules\\" -and
      $_.FullName -notmatch "\\dist\\" -and
      $_.FullName -notmatch "\\build\\"
    } |
    Select-String -Pattern "ghp_[A-Za-z0-9_]{10,}|github_pat_[A-Za-z0-9_]+|BEGIN .*PRIVATE KEY|SUPABASE_SERVICE_ROLE_KEY"
  ```

## 2. 데이터 및 사용자 패스워드 격리 검증

데모 상태에서 상용 상태로 전환하기 위한 자격증명 보정 여부입니다.

- [ ] **기본 PIN `0000` 가드**:
  - 소스코드에 하드코딩된 패스워드가 전면 제거되었는지 확인.
  - 가입한 학원 계정이 최초 생성될 때 시스템 PIN과 태블릿 PIN 값을 `0000`이 아닌 사용자 입력으로 강제 유도하는 가이드 포함 여부.
- [ ] **더미 데이터 격리**:
  - 실제 원격 DB 릴리즈 시, 테스트용으로 생성했던 다은이/제나 등의 더미 원생 정보(`students` 배열)가 상용 Production 스냅샷 테이블에 섞여 들어가지 않도록 Seeding 분리 규칙 정의 여부.
- [ ] **LocalStorage MVP 한계 극복 자각**:
  - 현재 LocalStorage 기반 환경에서 실제 학생 정보와 학부모 연락처를 업로드해 쓰면 개인 정보 보호법 위반 소지가 있습니다.
  - 테스트 및 프리뷰 릴리즈 배포 시에는 반드시 **더미 테스트 데이터**만 다루도록 사용자 계약 안내서나 경고창을 배치해야 합니다.

## 3. 역할별 시나리오 수동 체크 리스트

프리뷰 환경 호스팅 완료 후 3대 역할 동선에 대한 최종 리그레션 테스트를 완수해야 합니다.

- [ ] **원장(Director) 시나리오**:
  1. 원장 데모 로그인 선택.
  2. 대시보드 지표 카드 및 차트가 정상적으로 렌더링되는지 확인.
  3. 원생 관리 페이지에서 새 원생 추가 모달을 띄워 데이터 등록 후 테이블 갱신 확인.
  4. 설정 탭에서 학원 프로필 정보 업데이트 후 새로고침 시 정보 유지 확인.
- [ ] **강사(Teacher) 시나리오**:
  1. 강사 데모 로그인 선택.
  2. 오늘 수업 현황판 및 강사 시프트 페이지 작동 확인.
- [ ] **학부모(Parent) / 출결 태블릿(Kiosk) 시나리오**:
  1. 키오스크(출결) 모드 진입.
  2. 지정 PIN 코드를 눌러 등원/하원 처리 실행.
  3. 학부모 데모 로그인 진입 후 자녀의 등하원 출결 시간 실시간 갱신 확인.
  4. 수납 및 만족도 설문조사 응답 제출 확인.

## 4. 미연동 Mock 기능 주의 고지

현재 MVP는 완전한 비동기 백엔드 연결 전 단계이므로, 외부 네트워크 연동이 필요한 아래 기능들은 모킹 상태(`Mock service`)임을 릴리즈 안내 시 공시합니다.
1. **토스페이먼츠**: 실제 이체나 카드 결제 요청이 일어나지 않는 샌드박스 가상 결제창 테스트 상태입니다.
2. **카카오 알림톡**: 출결 마킹 시 실제로 카카오톡 알림이 발송되지 않으며 브라우저 상단 알림 및 로그로 대체됩니다.
3. **Supabase DB**: 실제 원격 연결이 없으며, 브라우저 로컬 저장소를 활용합니다.

## 5. 고객 테스터용 안내 문구 초안
배포된 프리뷰 링크를 학원 원장님 또는 테스트 사용자에게 공유할 때 전달할 공식 공지사항 양식입니다.

> **[DayDay MVP 테스터 안내문]**
>
> 본 서비스는 DayDay 음악학원 ERP MVP의 기능 검증용 프리뷰 버전입니다.
> 
> 1. **데이터 보호 안내**: 현재 버전은 별도의 영구 데이터베이스 없이, 접속하신 브라우저(로컬스토리지)에만 데이터가 저장됩니다. 브라우저 쿠키/캐시를 삭제하거나 시크릿 모드를 사용하실 경우 입력한 정보가 초기화되니 주의 부탁드립니다.
> 2. **더미 데이터 사용 권장**: 실제 학생의 주소, 전화번호 및 금융 결제 정보를 입력하지 마시고, 가상의 더미 데이터를 통해 수납과 출결 기능을 자유롭게 체험해 주시길 권장합니다.
> 3. **가상 연동 안내**: 수당 결제 및 카카오 알림톡은 가상의 샌드박스로 실행되어 실제로 요금이 청구되거나 메시지가 전송되지 않습니다.
