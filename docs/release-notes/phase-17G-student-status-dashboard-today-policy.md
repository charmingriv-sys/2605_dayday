# Phase 17G-Policy: 휴원/퇴원 상태의 오늘 콘솔/대시보드 반영 정책 설계서

본 문서는 튜링음악학원 DayDay 시스템에서 원생의 상태(`attending` / `on_leave` / `withdrawn`)가 오늘 원장 콘솔(todayTask) 및 대시보드 지표(KPI) 도메인에 미치는 비즈니스 영향과 상태 전환에 따른 정책적 예외 처리 방안을 정리한 정책 검토 및 설계 문서입니다.

---

## 1. 현재 오늘 콘솔/대시보드 구조 요약

* **오늘 콘솔 todayTask 생성 구조**:
  - `todayTask` 모듈은 원생별 출결, 수강료 미납, 교재 지급 상태 등을 추적하여 원장이 오늘 처리해야 할 과업(Task)을 화면에 생성하는 백오피스 서비스입니다.
* **미출결/결석 확인 task**:
  - 당일 등원 스케줄이 등록되었으나 출석 체크가 이루어지지 않은 경우(미출결), 혹은 결석 상태로 체크된 경우 원장이 학부모 포털에 출결 parentMessages를 보내거나 상황을 확인하도록 권장하는 태스크가 생성됩니다.
* **미납/수강료/교재비 task**:
  - 납부 희망일이 지났음에도 미납인 수강료 청구서, 혹은 배부일이 지났으나 미결제 상태인 교재비에 대해 수납 관리를 하도록 유도하는 업무 알림 태스크가 생성됩니다.
* **교재 관련 book_check 및 book_billing 구분**:
  - `book_check`는 실제 교재가 수강생에게 물리적으로 지급되었는지를 확인하는 태스크이며, `book_billing`은 지급된 교재에 대한 교재비 청구서가 발행 및 수납 처리되었는지 재무적 관점에서 추적하는 태스크입니다.
* **오늘 콘솔 연계 메시지 보내기 버튼과의 관계**:
  - `todayTask`에서 제공하는 오늘 콘솔 연계 메시지 보내기 버튼을 통해 수신자 정보(원생 및 보호자 연락처)를 메시지 작성 화면으로 연계하여, 수동 안내 문자를 즉시 보낼 수 있도록 연동하고 있습니다.

## 2. 사용자 결정 정책 반영 요약 (정책 방향 명시)

본 설계 단계에서는 다음 세 가지 사용자 정책 결정 사항을 **구현 시 준수할 정책 방향**으로 명확히 명시합니다.

1. **재원생 및 원생 상태 요약 카드 구성 (정책 방향)**:
   - 휴원생은 대시보드 상의 재원생 수에 포함시키지 않습니다.
   - 재원생 수 KPI는 오직 `attending` 상태 원생을 중심으로 집계하는 방향으로 설정하며, 휴원생 수는 별도의 단독 KPI 카드가 아니라 **"원생 상태 요약" 카드** 안에 포함하여 함께 표시하는 방향으로 설계합니다.
   - 원생 상태 요약 카드에는 **재원생 수 / 휴원생 수 / 퇴원생 수**를 나란히 표시하여 전체 원생 상태의 추이를 파악하는 방향으로 정리합니다. 휴원생은 재원생 수에 포함하지 않고 별도 값으로 분리합니다.
2. **퇴원생 미납 총액 KPI 처리 (정책 방향)**:
   - 퇴원생이 미납한 금액이 있더라도, 대시보드의 기본 미납 총액 KPI 지표에는 합산하지 않고 제외하는 방향으로 설계합니다.
   - 다만, 회계 누락 및 채권 관리 방지를 위해 퇴원생 미납 이력은 완전히 숨기지 않고 원생 상세 화면이나 미납 데이터 상세 내역 등 추적 경로를 유지하여 확인 가능하도록 정리합니다.
3. **출결률 집계 분모 설계 (정책 방향)**:
   - 휴원 중인 기간은 출결률 분모 집계 대상에서 제외하는 방향으로 설계합니다. 휴원 기간을 출결률 계산에 포함하면 지표가 무단결석처럼 왜곡되어 리포트 신뢰성을 떨어뜨릴 우려가 있습니다.
   - 정확한 일자 반영을 위해서는 `leaveStartDate`와 `leaveEndDate` 등 날짜 기간 필드가 필수적이므로, 날짜 필드가 데이터 모델에 정식 도입되기 전에는 성급히 로직을 구현하지 않고 보류합니다.

## 3. 상태별 오늘 콘솔 정책 후보 (Status-Based todayTask Candidates)

* **재원 (`attending`)**: 기존과 동일하게 모든 미출결, 미납, 교재 지급 task를 정상 생성합니다.
* **휴원 (`on_leave`) (정책 방향)**: 
  - 휴원 처리 시 **휴원 일정(시작일/종료일)을 설정**할 수 있어야 하며, 설정된 휴원 일정은 삭제되지 않고 회원 정보에 이력(history)으로 남아 원장이 언제든 조회할 수 있어야 합니다.
  - 휴원 기간 중에는 오늘 콘솔의 일반 출결/미등원 task에서 조용히 처리(제외하여 노출하지 않음)하는 정책 방향을 적용합니다.
  - 단, 휴원 마감일이 경과했음에도 재원으로 복귀하지 않는 등 후속 조치가 필요한 경우 오늘 콘솔에 경고 task를 노출하여 처리를 유도합니다.
  - 단일 status만으로 처리할 경우 소급 정산 및 기간 집계가 왜곡되므로, `leaveStartDate`/`leaveEndDate` 또는 `leaveSchedules[]` 같은 기간 데이터가 연계되어야 한다는 위험 경고를 강력하게 유지합니다.
* **퇴원 (`withdrawn`)**:
  - 퇴원일 이후 새롭게 스케줄링되거나 도래하는 업무(수강료 미납, 신규 교재 지급 등)에 대해서는 신규 todayTask 생성 후보를 보류하는 방안을 설계합니다.
  - 퇴원 이전에 생성되어 있던 과거 task 및 이력 로그는 완결성 및 히스토리 보존 원칙에 따라 그대로 보존합니다.

---

## 4. 미출결/출결 task 영향 후보 (Attendance Task Candidates)

* **상태별 출결 태스크 예외 처리 후보**:
  - 휴원 기간 또는 퇴원일 이후의 등원 스케줄 정보에서 발생하는 미출결/결석 경고 생성 후보를 보류하는 방향을 설계합니다.
  - 단, `leaveStartDate`/`leaveEndDate`/`withdrawalDate` 등 정밀한 날짜 데이터 필드가 마련되기 전까지는 status 기준의 기계적 제외를 보류하고, 수동 조치 대상 알림 가이드 후보로 접근합니다.
* **과거 출결 task 보존**:
  - 원생 상태 변경 시점 이전에 존재했던 모든 출결 점검 task 및 log는 세무/운영 데이터 무결성을 위해 훼손 없이 보존되어야 합니다.

---

## 5. 미납/수강료 task 영향 후보 (Billing Task Candidates)

* **퇴원생 미납/교재 task 관리 방향 (정책 방향)**:
  - 퇴원생의 미납 원비 및 미납 교재비 관련 task는 원장이 직접 처리하거나 삭제하기 전까지는 오늘 콘솔에 지속해서 노출하는 방향으로 정리합니다.
  - 태스크에 대해서는 단순 삭제뿐 아니라, **"미납 아님 처리", "종결 처리", "수납 완료 처리", "메모 작성"** 등의 다각적인 수동 처리 후보군을 함께 지원하여 원장의 관리 편의를 돕습니다.
  - 퇴원생 미납 task를 성급히 화면에서 은닉하면 회계 미수금 누락 위험이 매우 크므로, 기존의 task/history/log 데이터는 임의 삭제하지 않는 보존 방향을 확고하게 유지합니다.
* **퇴원생 미납 채권 상세 추적 및 경로 확정 (정책 방향)**:
  - 퇴원생 미납 상세 조회 경로는 추가적인 메뉴 신설 없이 다음 2가지로 확정합니다:
    1. **미납자 명단 상세 페이지 내 필터 스위치**
    2. **원생 상세 정보 모달 내의 수납/결제 탭**
  - 별도의 독자적인 미납금 추적 전용 메뉴 신설은 이번 범위에서 제외하고 후속 Phase 후보로만 열어 둡니다.
* **휴원 정기 청구 연동 후보**:
  - 휴원 중 정기 청구 보류/감면/이월 정책 설계와 연동하여, 청구서 발행이 유예되거나 보류된 대상에 한해 미납 점검 task 생성을 보류하는 후속 Phase 설계 가이드를 둡니다.

---

## 6. 교재 task 영향 후보 (Book Task Candidates)

* **기 지급 교재 및 미납 교재비 task 보존**:
  - 휴원/퇴원 상태로 전환되더라도 이미 지급이 완료되었던 교재(`book_check`) 이력 및 이미 청구되어 미납된 상태인 교재비(`book_billing`) task는 보존되어야 합니다.
* **신규 지급 점검 태스크 제어 후보**:
  - 상태가 `on_leave` 또는 `withdrawn`인 원생에 대해서는 신규 교재 지급 점검 태스크 생성을 유보하는 후보를 검토합니다.
  - 신규 교재 등록일이 퇴원일보다 늦은 시점인 경우, 교재 점검 권장 경과일 기준에 따라 업무 추천 리스트에 나타나지 않도록 제한하는 조건을 설계합니다.

## 7. 대시보드 KPI 영향 후보 (Dashboard KPI Candidates)

| 대시보드 지표 | 상태 반영 설계 방향 (정책 방향으로 명시) | 구현 전 제약 사항 |
| :--- | :--- | :--- |
| **재원생 수** | **`attending` 원생 중심 집계 ("원생 상태 요약" 카드 내 표시 방향)** | KPI 상세 정의 수립 전 UI 구현 금지 |
| **휴원생 수** | **재원생 수에서 제외, "원생 상태 요약" 카드 내에 함께 표시하는 방향** | 날짜 필드(휴원 기간) 데이터 도입 후 정밀 집계 |
| **퇴원생 수** | **"원생 상태 요약" 카드 내에 함께 표시하는 방향** | 누적 통계 데이터 저장 구조 후속 검토 |
| **미납 총액** | **전체 미납 총액을 보여주되 재원/휴원 미납과 퇴원생 미수금을 분해 표시하는 후보 (정책 방향)** | 최종 UI 구성은 후속 Phase에서 확정하는 후보로 작성 |
| **출결률** | **휴원 기간을 집계 분모에서 제외하는 방향** | `leaveStartDate`/`leaveEndDate` 입력 모델 필수 |

* **대시보드 수납/결제 안내 인포 가이드 방향 (정책 방향)**:
  - 대시보드 화면상에 상시 긴 문구를 노출하여 UI를 혼잡하게 만드는 방식을 피하고, KPI 카드 영역 또는 필터 영역 근처에 **`i` 인포 버튼(툴팁 및 안내 팝오버 후보)**을 배치합니다.
  - 원장이 인포 버튼을 클릭하거나 마우스를 호버할 때 아래의 안내 문구를 툴팁 또는 작은 안내 팝오버 형태로 띄워 보여주는 후보로 기술합니다.
    - *“수납 및 결제 현황은 퇴원생을 포함한 전체 이력 기준입니다.”*
    - *“대시보드 기본 미납 KPI와 집계 기준이 다를 수 있습니다.”*
* **미납 KPI 정책 보정 및 분해 표시 후보 (정책 방향)**:
  - 기존의 "퇴원생 미납은 대시보드 기본 미납 총액 KPI에서 제외"라는 기술 방식이 오늘 콘솔 상의 미납 task 노출 정책과 상충 및 혼동될 여지가 있음을 명시합니다.
  - 이에 따라 대시보드 미납 KPI 추천 방향은 **"전체 미납 총액을 제공하되, 재원/휴원생 미납과 퇴원생 미수금을 분해하여 명시하는 후보"**로 보정합니다.
    - *미납 총액 (합계)*
    - *재원/휴원생 미납액*
    - *퇴원생 미수금*
  - 다만 구체적인 지표 렌더링 및 최종 UI 화면 구현 스펙은 후속 Phase에서 안전하게 확정하는 후보 표현으로 정리합니다.

## 8. 원장 화면 필터/표시 후보 (Director View UI Candidates)

* **오늘 콘솔 상태 배지 표시 후보**:
  - 오늘 할 일 리스트의 각 task 카드 내 원생 이름 옆에 `[휴원]`, `[퇴원]` 상태 배지를 렌더링하여 원장이 인지할 수 있도록 돕는 UI 후보를 검토합니다.
* **필터 조건 설정 후보**:
  - 오늘 콘솔 내에서 휴원생 관련 task를 기본적으로 표시할지 여부와, 퇴원생의 과거 task/log를 노출 및 필터링할 수 있는 스위치를 제공할지 후보를 검토합니다.
  - 미수금/미납 처리가 완료되지 않은 비활성 원생을 오늘 콘솔에서 완전히 숨기면 채권 누락 위험이 있으므로, 가시성을 유지하는 정책 후보를 우선 설계합니다.

---

## 9. 오늘 콘솔 연계 메시지 보내기 버튼 영향 후보 (Today Console Link Candidates)

* **오늘 콘솔 연계 메시지 보내기 버튼 노출 여부 및 유지 방향 (정책 방향)**:
  - 휴원/퇴원 상태 관련 task에서도 오늘 콘솔 연계 메시지 보내기 버튼은 그대로 유지하는 방향으로 정리합니다.
  - 다만, 발송 실수 방지를 위해 해당 버튼 클릭 시 상태 배지와 발송 전 경고 안내를 결합하여 함께 제공하는 방향으로 정리합니다.
  - 실제 SMS/알림톡 연동 후보 단계에서는 과금 및 오발송 위험 때문에 더 엄격한 확인 가드 후보를 후속 Phase로 검토하여 연동 오해를 없애도록 합니다.
* **교재 및 수납 업무 추천 충돌 검토**:
  - 수강료 미납(`book_billing`)은 퇴원생이라도 수동 독촉을 허용하는 방향이 타당할 수 있으나, 단순 교재 수령 체크(`book_check`)는 퇴원생인 경우 오늘 콘솔 연계 메시지 보내기 버튼의 필요성이 낮으므로 task 성격에 따라 차등 적용하는 후보를 검토합니다.

## 10. 사용자 정책 확인 필요 사항 (User Decision Questions)

구현 단계 착수 전, 아직 미정으로 결정되지 않은 다음 정책 결정 후보군에 대하여 원장의 확인 및 의사결정이 필요합니다. (이미 결정된 지표 분리, 요약 카드 통합, 퇴원생 상세 조회 경로 확정 및 오늘 콘솔 연계 메시지 보내기 버튼 유지 정책은 정책 설계 본문에 반영되었습니다.)

1. **오늘 콘솔 휴원생 task 기본 노출 설정 후보**:
   - **대안 A**: 휴원생 관련 task(예: 기존 미납금 등)는 오늘 콘솔에서 기본 표시하는 후보.
   - **대안 B**: 휴원생 관련 task는 기본적으로 숨기고 별도 필터 클릭 시 노출하는 후보.
2. **퇴원생 과거 미납/교재 task 노출 정책 후보**:
   - **대안 A**: 미납 채권 회수를 돕기 위해 퇴원생의 미납/교재 관련 미결 task를 완료 처리 전까지 계속 보여주는 후보 (이용자가 직접 처리하기 전까지 콘솔 노출 방향).
   - **대안 B**: 퇴원생의 미결 task는 퇴원 완료 시점에 일괄 종결 처리하고 더 이상 콘솔에 띄우지 않는 후보.

## 12. 위험 및 주의사항 요약 (Summary of Risks)

* **비활성 task 무조건 삭제 시 운영 단절 리스크**:
  - status가 바뀌었다는 이유로 오늘 콘솔의 기존 task들을 일괄 삭제하거나 숨기면, 진행 중이던 업무 인수인계나 과거 미납 건 회수 등 학원 운영 관리에 공백이 생길 위험이 큽니다.
* **퇴원생 미납 채권 은닉으로 인한 회계 사고 리스크**:
  - 대시보드 KPI 노이즈 방지를 위해 퇴원생 미납금을 단순히 화면에서 보이지 않게 처리하고 상세 추적 경로를 마련해 두지 않으면, 미수금 누계 세무 통계가 어긋나 회계 사고로 이어질 위험이 큽니다.
* **출결 지표 왜곡 및 성급한 구현 리스크**:
  - 휴원 기간을 등원 스케줄로 오인해 출결률 분모에 넣으면 지표가 급격히 떨어지는 왜곡이 발생합니다. 하지만 날짜 정보가 없는 현시점에 status만으로 무리하게 이를 구현하면 과거 재원 중이었던 출결 리포트마저 훼손될 수 있으므로, 기간 날짜 모델 도입 시까지 반영을 보류하는 방안이 타당합니다.
* **장식용 대시보드 UI 개발 리스크**:
  - 데이터 필드 정의 및 통계 모델 정립 없이 모니터 링커 화면의 UI부터 성급하게 개발하는 경우, 실시간 렌더링 부하만 가중시키고 현업에 도움이 되지 않는 단순 장식성 화면이 될 위험이 있습니다.
