# 강사 라이프사이클 정책 (Teacher Lifecycle Policy)

본 문서는 음악학원 강사 정보의 등록, 퇴사 처리, 물리 삭제 조건 및 과거 데이터 보존에 대한 정책을 정의합니다.

---

## 1. 강사 상태값 정책 (Teacher Status)

모든 강사 데이터는 관리 상태를 구분하기 위해 `employmentStatus` 필드를 필수적으로 가집니다.

* **활성 강사 (`active`)**
  * 학원에 정상적으로 출근하여 수업을 매칭받는 현재 재직 중인 강사입니다.
  * 데이터 속성: `employmentStatus: "active"`, `resignedAt: null`, `resignMemo: ""` (또는 누락 시 자동 보정)
* **퇴사 강사 (`resigned`)**
  * 학원 근무를 종료(퇴사)하여 더 이상 신규 수업 배정 및 출퇴근 체크를 진행하지 않는 강사입니다.
  * 데이터 속성: `employmentStatus: "resigned"`, `resignedAt: "YYYY-MM-DD"`, `resignMemo: "사유 기술"`

---

## 2. 퇴사 처리 정책 (Resignation Process)

* 기존에 출퇴근 체크 이력이나 담당 학생 매칭 이력이 있는 강사는 개인정보 및 과거 레슨 데이터 보존을 위해 **물리적으로 삭제하지 않고 퇴사(`resigned`) 처리하는 것을 원칙**으로 합니다.
* 퇴사 처리 시 아래의 데이터를 필수/선택적으로 기록합니다.
  * `resignedAt` (필수): 퇴사 처리일 혹은 퇴사일자 (형식: `YYYY-MM-DD`)
  * `resignMemo` (선택): 퇴사 사유 또는 기타 특이사항 (기본값: 빈 문자열 `""`)
* 퇴사 상태로 전환된 강사는 `updatedAt`이 함께 기록되며, 시스템 내의 활성 목록에서 제외됩니다.

---

## 3. 삭제 정책 (Physical Deletion)

* **물리 삭제 제한**: 데이터베이스의 참조 무결성과 정산/출결 레포트의 신뢰성을 보장하기 위해, 다른 데이터 도메인과 연결 기록(Foreign Key / Reference)이 하나라도 존재하는 강사의 물리 삭제는 **절대적으로 금지**되며, 퇴사 처리로만 유도해야 합니다.
* **삭제 허용 조건**: 강사 데이터를 오등록하였거나, 등록 직후 아무런 스케줄 배정 및 근태 활동 없이 바로 취소하는 등 **연결된 과거 기록이 전혀 존재하지 않는 강사**에 한해서만 물리 삭제(`deleteTeacherIfUnused`)를 허용합니다.
* **연결 검사 대상**: 삭제 요청 시 아래의 데이터 도메인에 해당 강사에 대한 참조가 존재하는지 확인합니다.
  1. **강사 근태 기록 (`teacherAttendanceLogs`)**: 강사가 출근/퇴근을 기록한 이력
  2. **강사 일정 및 타임테이블 (`teacherShifts`)**: 일별 강사 타임테이블 설정 내역
  3. **수강생 정보 (`students`)**: 해당 강사를 담당 강사(`teacherId`)로 두고 있는 학생
  4. **수업 시간표 스냅샷 (`scheduleSnapshots`)**: 수업 출결 처리를 위해 고정된 특정 일자의 스케줄 스냅샷 엔트리
  5. **수업 일정 변경 이력 (`scheduleOverrides`)**: 강사 변경, 시간 변경 등 수강생 수업 시간표 오버라이드 내역
  6. **시간표 조작 로그 (`scheduleOperationLogs`)**: 일별 시간표 배정/변경 조작 내역 로그
  7. **학원 주요 일정 (`majorSchedules`)**: 콩쿠르, 정기 연주회 등의 담당자(`ownerId`가 강사 이름과 매칭)
     * *주의*: 주요일정 담당자 연결은 현재 DB 구조상 강사명 기반 문자열로 검사하므로, 이름 변경이나 동명이인 발생 시 취약할 수 있습니다. 추후 `majorSchedules.ownerId`를 `teacherId` 기반으로 전환하는 리팩토링이 필요합니다.
* 삭제 시도가 위 조건 중 하나라도 충족하여 거부되는 경우, 삭제 사유(연결된 데이터 내역)를 반환하고 기존 강사 데이터는 안전하게 보존합니다.

---

## 4. 과거 기록 보존 정책 (History Preservation)

* 퇴사 상태(`resigned`)의 강사라 하더라도, 과거의 출퇴근 대장, 정산 보고서, 학생 레슨 히스토리, 주요 일정 담당자 정보 등에서는 **강사의 실명이 그대로 보존되어 출력**되어야 합니다.
* 퇴사한 강사명을 잃지 않음으로써 원장이 과거 기록을 조회할 때 데이터의 왜곡이 발생하지 않도록 합니다.
* **UI 표시 가이드라인**:
  * 과거 기록 뷰에서 퇴사 강사는 이름 옆에 **`[퇴사]` 배지**를 붙이거나, 텍스트 색상을 **연한 회색 톤**으로 흐리게 처리하여 직관적으로 재직 상태가 아님을 나타냅니다.
  * 담당자 필드를 하이픈(`-`) 처리하는 것은 담당 강사가 명확하게 '미지정'되었거나 실제로 담당자 정보가 없는 빈 데이터일 경우에만 제한적으로 적용합니다.

---

## 5. 신규 배정 및 선택 정책 (Future Assignment)

* 신규 수강생 등록 시 담당 강사 지정, 수업 시간표의 배정, 태블릿 Kiosk 출퇴근 체크의 기본 목록 등 **새로운 액션을 수반하는 모든 선택 목록(Select Box / Modal)에서는 퇴사 상태의 강사를 원천 배제(숨김)**합니다.
* 퇴사 강사를 숨김 처리함으로써 원장의 조작 실수를 예방합니다.
* 특정 사유로 퇴사한 강사의 과거 이력을 굳이 신규 매칭 UI에서 찾고자 할 경우에는, 추후 별도의 "퇴사 강사 포함 보기" 토글 등의 명시적 옵션을 통해서만 노출될 수 있도록 설계합니다.

---

## 6. 향후 백로그 (Backlog / Future Enhancements)

* **복직 처리 기능**: 실수로 퇴사 처리했거나 재입사한 강사를 다시 활성 상태(`active`)로 되돌릴 수 있는 복직 API 구현
* **퇴사 강사 포함 조회**: 강사 목록 관리 UI에서 퇴사한 강사까지 필터링하여 이력 조회가 가능하도록 토글 스위치 지원
* **생명주기 Audit Logs**: 강사의 퇴사, 삭제, 복직 이벤트 발생 시 `teacherAttendanceEditLogs` 처럼 변경 로그를 별도 로깅하는 기능 추가
* **강사 관리 화면 연동**: 원장 대시보드 강사 관리 탭 내에 "퇴사 처리" 및 "삭제" 버튼 추가 및 상기 API와 연동
