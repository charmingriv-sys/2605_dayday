# Phase 8C Today Console Deferred Decisions & Backlog

## 1. 문서 목적
* 작은 Phase로 나누어 개발을 진행하더라도 사용자 요구사항과 장기적인 운영 인사이트가 유실되지 않도록 보존합니다.
* 본 문서의 각 항목은 추후 사용자와 재논의하여 **구현, 보류, 드롭** 중 하나로 결정합니다.

## 2. Deferred Decisions / Backlog 목록

### A. 시간 선택 UX
* **오전/오후 - 시간 - 분** 순서로 직관적으로 선택하는 커스텀 UI.
* 분 선택은 **5분 단위**로 제한하여 빠른 입력 지원.
* 키보드 텍스트 입력보다 마우스/터치 선택형 UI 중심 구성.
* 날짜/시간 필드는 일반 input 필드처럼 보이기보다, 클릭 시 즉시 선택형 드롭다운/다이얼로그 진입하도록 개선.
* 시작시간 변경 시 종료시간 자동 연동 (+1시간).
* 사용자가 종료시간을 직접 수정(오버라이드)한 경우, 이후 시작시간을 변경하더라도 수동 설정값을 덮어쓰지 않도록 처리.

### B. 운영대기업무 정렬 정책
* 현재는 `priority`/`category` 기반 임시 정렬 가중치가 적용됨.
* 향후 업무 흐름에 맞춰 `startAt`/`endAt` 기반의 **시간순 정렬**로의 전면적인 전환 검토.
* 하단 캘린더/타임라인 병렬 레이아웃과 연동하여 시각적 직관성 확보.

### C. 완료 업무 표시 정책
* 현재는 완료/보류/숨김 처리 시 active queue에서 바로 삭제되는 임시 방식.
* 향후 완료(done)된 항목은 회색톤, 불투명도 조절, 취소선 등을 적용해 **완료 상태로 화면에 유지**하는 정책 필요.
* 원장이 하루 동안 어떤 일들을 처리했는지 퇴근 전 한눈에 회고(Retrospective)할 수 있어야 함.

### D. 운영대기업무 + 캘린더 병렬 레이아웃
* **좌측**: 운영대기업무 큐 (Active Queue)
* **우측**: 일간 캘린더 / 타임라인 (Day Timeline)
* 원장이 학원 운영 중 항상 띄워놓고 관제하는 **대시보드형 관제 화면**이 최종 지향점.
* 오늘 할 일(업무)과 일정(캘린더 이벤트)이 하나의 뷰에서 상호 유기적으로 연동되어야 함.

### E. App Calendar / mockCalendarEvents
* 실제 Google Calendar 연동 이전에 로컬 앱 전용 캘린더 기능 구현.
* `mockCalendarEvents` 데이터를 기반으로 학원 내부 일정을 타임라인에 렌더링.
* `TodayTask` 중 `startAt`/`endAt`이 설정된 업무 카드들도 캘린더 타임라인 상에 일간 일정과 병합 표시.

### F. Google Calendar 실제 연동
* Phase 8D 이후 우선 읽기 전용(Read-only) 연동부터 구현.
* OAuth 및 API 연동 로직은 반드시 **Provider Layer**로 모듈화하여 분리.
* `TodayTask` 뷰 코드 내부에서 API를 직접 호출하지 않는 구조 유지.
* App Calendar 일정과 Google Calendar 일정을 하나의 타임라인에 병합하고 중복 일정을 제거하는 로직 필요.

### G. 구분 (Category) 관리
* **MVP 기본 구분**: 메모, 상담예약, 확인필요, 마감체크.
* 향후 원장이 설정 화면 등에서 직접 카테고리를 추가/수정/삭제할 수 있는 CRUD 지원.
* **Segment Config** 또는 별도의 사용자 settings를 통한 관리 후보.
* 구분(category)은 작업의 우선순위(priority)와 성격이 다르므로 물리적/의미론적으로 완전히 분리해야 함.

### H. 원장 콘솔 전체 UX 재검토 (Delight Loop & 관제)
* 단순한 TODO 리스트가 아니라, 학원 운영의 중심 관제 화면 역할 수행.
* 출결, 결제, 교재, 리스크, 상담, 픽업, 학부모 액션이 유기적으로 흐르는 UI/UX 설계.
* 아이들과 학부모가 경험할 긍정적인 가치(Delight Loop)를 극대화하는 UX 요소 고려.
* 한번 켜면 업무가 끝날 때까지 닫고 싶지 않은 흡입력 있는 UI 제공.

## 3. Phase 연결 제안
* **Phase 8C-3A-2**: 커스텀 시간 선택 UX (오전/오후-시-분 선택 및 5분 단위)
* **Phase 8C-3B**: 완료 업무 보존 표시 및 취소선/회색톤 UI 처리
* **Phase 8C-3C**: 운영대기업무 + 캘린더 병렬 레이아웃 구성
* **Phase 8C-3D**: `mockCalendarEvents` 기반 App Calendar 표시
* **Phase 8C-3E**: `startAt`/`endAt` 기반 업무 시간순 정렬 정책 전환
* **Phase 8D**: Google Calendar read-only Provider 연동 (Provider 모듈 설계 포함)
* **Phase 8E 이후**: category CRUD 및 사용자 설정(settings) 화면 구현

## 4. 운영 원칙
* 매 Phase 시작 전 반드시 이 백로그 문서를 사전 점검하고 최신화합니다.
* 현재 구현하지 않는 항목은 삭제(Drop)하지 않고, 반드시 **"보류(Deferred)"** 상태로 관리합니다.
* 사용자와의 사전 확인 및 동의 없이 백로그 항목을 임의로 제거하지 않습니다.
