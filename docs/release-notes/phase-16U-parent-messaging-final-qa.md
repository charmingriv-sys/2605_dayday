# Phase 16U: 학부모/원장 메시징 통합 최종 QA 완료 보고서

본 문서는 Phase 16I부터 16T까지 진행된 학부모 메시징, 원장 메시지 보내기, 학부모 포털, 그리고 오늘 원장 콘솔 Handoff 흐름에 대한 최종 구현 및 수동 QA Repair 결과를 포함하는 최종 검증 요약 문서입니다.

## 2. Phase 16I ~ 16T 구현 요약

- **Phase 16I (parentContacts & parentMessages 기본 스키마)**: 본인/보호자1/보호자2 구조의 수신처 매핑 스키마 및 등하원/수납 발송 이력 스키마 설계.
- **Phase 16J (원생 정보 보호자 1/2 UI)**: 원생 상세 뷰 내 보호자 1/2의 연락처, 관계, 메시지 수신 여부, 대표 지정 UI 구현.
- **Phase 16K (학부모 메시지/푸시 설정)**: 학원정보관리 내 등원, 하원, 수납, 교재비 등 8가지 이벤트별 메시지함 저장 및 푸시 활성화 토글 탑재.
- **Phase 16L (등하원 parentMessages)**: 태블릿 키오스크 등하원 시, 원장의 설정 값에 부합하는 parentMessages 자동 생성 및 무발송 조건(안함 설정 등) 처리.
- **Phase 16M (수강료/교재비 parentMessages)**: 수강료 청구, 미수납, 수납 완료 및 교재비 청구, 미수납, 수납 완료 시점의 parentMessages 자동 생성 처리.
- **Phase 16N (학부모 포털 출결/결제/코멘트/알림 구조)**: 학부모가 로그인하여 본인 자녀의 등하원 이력, 결제 상태(미수납/완료), 코멘트 피드 및 알림 목록을 확인하는 통합 뷰 구축.
- **Phase 16O (원장 메시지 보내기 수신자/검토 모달/템플릿)**: 발송 전 이름 매크로(`#{이름}`)가 치환된 개별 미리보기 아코디언 제공 및 9종 템플릿 선택 초안 덮어쓰기 가드 구현.
- **Phase 16P (오늘 원장 콘솔 handoff)**: 오늘 콘솔 내 미수납/결석 등 원생 태스크 카드에서 [메시지 보내기] 클릭 시, 수신자 보호자1 및 매칭 템플릿 본문(시간 등 치환)을 session을 통해 이동 자동 기입하는 Handoff 흐름 구축.
- **Phase 16Q (통합 점검)**: 원장/학부모 포털 양방향 상태 동기화 및 E2E 시나리오 보강.
- **Phase 16R (SMS/알림톡 설계)**: 실제 이동통신망 발송 전의 메시지 라우팅 구조 및 발송 대기 큐 설계.
- **Phase 16S (Push/앱 설치 상태 설계)**: 학부모 전용 앱의 FCM/APNs 토큰 등록 및 알림 수신 동의 연동 사양 설계.
- **Phase 16T (수동 QA Repair)**: 실 환경 수동 검증 중 도출된 UI 불안정성, Handoff UX 보완, 클릭 안 됨 오류, 지각 잔존 및 달력 크기 버그, 탭 노출/순서 설정 기능을 집중 개선.

## 4. 현재 확정된 핵심 정책

1. **메시지 수신처 제어**:
   - 메시지 보내기 진입 시 **보호자1**이 기본 활성화(ON)됩니다. 본인 및 보호자2는 원장이 필요 시 수동으로 토글 선택할 수 있습니다.
2. **이름 매크로 치환**:
   - 본문 내 적힌 `#{이름}` 매크로는 보호자 실명이 아닌 **원생의 실제 이름**으로 파싱되며, 발송 직전 확인 모달에서 개별 원생별로 치환 결과를 아코디언 검토할 수 있습니다.
3. **태스크 수명 및 메시지 연결 규칙**:
   - 오늘 원장 콘솔의 업무 카드에서 [메시지 보내기]로 이동해 발송을 완료하더라도, 콘솔 내 태스크는 자동으로 완료 처리(done)되지 않습니다 (원장의 최종 최종 확인을 위해 Open 상태 보존).
   - 교재 확인(`book_check`) 업무 카드는 발송 제외 대상이며, 교재비 미수납(`book_billing`) 업무는 [메시지 보내기] Handoff 연동을 허용합니다.
4. **학부모 화면 Source-of-Truth**:
   - 학부모 포털의 출결 달력과 수강료 납부 카드는 보조 메시지 데이터인 `parentMessages`가 아니라, 원장의 데이터베이스 원장부 테이블(`attendance`, `billing`)을 Source-of-Truth(진실의 원천)로 삼아 화면을 그립니다.
   - `parentMessages`는 오직 읽지 않은 미확인 배지(`unread`/`read`) 상태를 표시하고 소거하기 위한 인디케이터 데이터로만 격리 사용됩니다.
   - 자동 생성되는 등하원/수납 알림(`parentMessages`)은 학부모의 '알림 및 설문' 목록 탭에 섞이지 않고 격리됩니다.
5. **알림 및 설문 탭 관리**:
   - 학부모 화면의 탭은 설정에 따른 ON/OFF를 준수하며, 순서는 항상 `공지사항 -> 설문조사 -> 안내사항`을 유지합니다.
   - 모든 탭을 OFF 할 경우, 비정상 화면 예방을 위해 "현재 표시 중인 알림 및 설문 항목이 없습니다."라는 대체 문구를 보여줍니다.
   - 설문조사 카드는 학부모가 상세 내용을 확인(클릭)하면 미확인이 즉시 해제되며, 이는 설문 문항의 답변 제출 여부와 별개로 동작합니다.
6. **API 연동 한계**:
   - 실제 통신망 연동(SMS, 카카오 알림톡, FCM/APNs Push)은 지원하지 않으며, 목업 처리된 로컬 상태 저장소 범위 내에서 동작합니다.

## 6. 남은 수동 확인 항목

운영/스테이징 배포 단계에서 검토해야 할 실 모니터링 체크리스트입니다.

1. **메시지 보내기 발송 전 확인 모달의 정보량 검토**:
   - 다수의 원생(예: 30명 이상)을 동시 선택하여 즉시 발송을 누르는 경우, 모달 내 접기/펼치기 리스트의 로딩 속도 및 스크롤 감각이 적절한지 여부.
2. **Handoff 안내 배너 및 복귀 흐름의 조작 편의성**:
   - 원장이 Handoff 진입 후 배너를 확인하고, 발송 후 오늘 콘솔로 복귀하는 confirm 흐름이 사용자 인터뷰 상에서 거부감이 없는지 피드백 수집 필요.
3. **출결 달력 compact 뷰의 화면 적합성**:
   - 데스크톱뿐만 아니라 다양한 학부모 사용 기기(태블릿, 모바일 기기 브라우저)에서 달력의 셀 폰트와 크기가 가독성을 보장하는지 확인.
4. **학부모 포털 미확인 인디케이터 점(Red Dot) 가독성**:
   - 리스트형 카드 및 사이드바 배지의 색상이 배경 UI에 묻히지 않고 눈에 잘 띄는지 시인성 확인.
5. **알림 및 설문 탭 OFF/ON 설정 문구 직관성**:
   - "문자, 알림톡, 앱 푸시 발송 설정과는 별개"라는 의미와 "기존 데이터는 삭제되지 않고 학부모 탭만 제어한다"는 한글 안내 문구가 원장님들에게 직관적으로 이해되는지 확인.

## 7. 명시적 보류/제외 항목 (Out of Scope)

* 실제 외부 이동통신망 SMS API 연동 및 LMS 분기 로직
* 비즈뿌리오 등 카카오 알림톡 발송 대행사 API 연동

* 카카오 알림톡 템플릿 심사 및 사전 등록(Registry) 시스템
* 메시지 보내기 컴포넌트의 새창(Window popup) 또는 완벽한 독립 모달 구조로의 분리
* 원장 및 소속 강사 대상 근태 경고용 인앱 푸시 발송
* 실 연동에 따른 LMS/알림톡 발송 과금 리포트 및 정산 분석 화면

- **Phase 16Z**: 운영 서버 릴리즈 전 통합 인수 테스트 시나리오 검토 및 데이터 백업 자동화 설계.
