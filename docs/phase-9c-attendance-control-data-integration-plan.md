# Phase 9C: 출결관제 실데이터 연결 및 워닝 로직 설계

본 문서는 출결관제 페이지의 UI 스켈레톤을 DayDay 앱의 실제 데이터베이스 상태(`stateStore`)와 유기적으로 연결하고, 수업 횟수 비례형 출결 워닝 알고리즘을 설계하기 위한 기술적 청사진입니다. 한글 인코딩은 UTF-8을 준수합니다.

---

## 1. 현재 데이터 구조 조사 결과

DayDay 앱은 `src/js/state/` 하위 모듈과 `localStorageAdapter.js`를 통해 객체 관계형 메모리 내 데이터베이스를 유지하고 로컬 저장소에 영속화하고 있습니다. 조사된 핵심 컬렉션 구조는 다음과 같습니다.

### A. 원생 데이터 (`db.students`)
* **식별 키**: `id` (예: `"S1"`, `"S2"`)
* **필요 필드**:
  - `name`: 원생 성명
  - `phone` / `parentPhone`: 비상 연락처
  - `teacherId`: 담당 주강사 ID
  - `instrument`: 수강 악기/과목 (예: `"피아노"`, `"바이올린"`)
  - `fee`: 월 수강료 (수납 상태 계산용)
  - `dueDay`: 매월 수납 지정일
  - `studentMemberNo`: 원생 회원번호 (검색 매칭 키)
  - `paymentStatus`: 수납 구분 (`"paid"` | `"unpaid"`)
  - `isDeleted`: 탈퇴/삭제 구분 플래그

### B. 강사 데이터 (`db.teachers`)
* **식별 키**: `id` (예: `"T1"`, `"T2"`)
* **필요 필드**:
  - `name`: 강사 성명
  - `instrument`: 전문 악기 분야

### C. 악기/반 데이터 (`db.subjects`)
* **식별 키**: `id` (예: `"SUB1"`, `"SUB2"`)
* **필요 필드**:
  - `name`: 과목명 (피아노, 바이올린, 첼로, 플루트, 기타)
  - 원생의 `instrument` 필드가 이 과목 데이터와 1:1로 매핑됩니다.

### D. 정규 수업 스케줄 데이터 (`db.classes`)
* **식별 키**: `id` (예: `"C1"`, `"C2"`)
* **필요 필드**:
  - `studentId`: 수강 원생 ID
  - `dayOfWeek`: 수업 요일 (`"월"`, `"화"`, `"수"` 등)
  - `time`: 수업 시작 시간 (예: `"14:00"`, `"15:30"`)

### E. 일자별 스케줄 스냅샷 및 오버라이드 (`db.scheduleSnapshots` & `db.scheduleOverrides`)
* **과거 및 오늘 날짜**: 시간표 드래그앤드롭 이동 등을 영속화하기 위해 `db.scheduleSnapshots` 내 `entries`로 수업 정보 보존.
* **미래 날짜**: 정규 시간표에서 개별 날짜별로 변경된 임시 일정은 `db.scheduleOverrides`에 타겟 날짜(`date`), 변경 대상 강사(`toTeacherId`), 변경 시간(`toStartTime`)을 매핑하여 오버라이드.
* **통합 API**: `stateStore.getTeacherStudentScheduleForDate(date)` 호출을 통해 과거 스냅샷과 미래 오버라이드가 반영된 완벽한 일자별 예정 수업 목록 획득 가능.

### F. 출결 데이터 (`db.attendance`)
* **식별 키**: `id` (예: `"A1"`, `"A2"`)
* **필요 필드**:
  - `studentId`: 원생 ID
  - `date`: 등원 일자 (`"YYYY-MM-DD"`)
  - `status`: 출결 상태 (`"present"` | `"late"` | `"absent"`)
  - `time`: 등원 태깅 시각 (예: `"14:02"`)
  - `leavingTime`: 하원 태깅 시각 (예: `"15:20"`)
  - `note`: 특이사항 및 결석 사유

### G. 메시지 발송 이력 (`db.messages`)
* **식별 키**: `id` (예: `"MSG1"`)
* **필요 필드**:
  - `studentId`: 수취 원생 ID
  - `title` / `content`: 메시지 본문 요약
  - `date` / `created_at`: 발송 시점 정보
  - 알림톡 발송은 custom DOM event(`kakaotalk-alert`) 발행과 동시에 `messages` 이력에 저장됩니다.

## 2. 사용할 수 있는 기존 stateStore API

| API 시그니처 | 위치 | 용도 및 설명 |
| :--- | :--- | :--- |
| `getStudents()` | `members.js` | 전체 활성 원생 목록 획득 |
| `getTeachers()` | `staff.js` | 전체 강사 목록 획득 |
| `getAttendance()` | `attendance.js` | 전체 출결 레코드 리스트 획득 |
| `getAttendanceForStudent(studentId)` | `attendance.js` | 특정 원생의 개인 출결 히스토리 조회 |
| `getTeacherStudentScheduleForDate(date, options)` | `sessions.js` | 과거 스냅샷 및 미래 오버라이드가 완벽 결합된 특정 일자 예정 수업 목록 조회 |
| `getMessagesForStudent(studentId)` | `communication.js` | 특정 원생에게 발송된 알림장/알림톡 이력 조회 |
| `markAttendance(studentId, date, status, time, note)` | `attendance.js` | 등원/지각/결석 상태 등록 및 알림톡 트리거 |
| `leaveAttendance(studentId, date, time)` | `attendance.js` | 하원 시간 기록 및 하원 알림톡 트리거 |
| `getTodayTasks()` | `todayTask.js` | 오늘 할 일 (시스템 지연 추천 포함) 목록 조회 |
| `updateTodayTask(taskId, data)` | `todayTask.js` | 출결 처리에 따른 지연 추천 완료(`done`) 상태 업데이트 |

### 추가가 필요한 Selector 후보 (State 모듈 내 정의 예정)
* **`getStudentAttendanceStats(studentId, startDate, endDate)`**: 지정된 기간 내 예정 수업 횟수 대비 실제 출석/지각/결석률을 비율(%) 기반으로 계산하여 뷰 로직의 캡슐화를 돕는 헬퍼 API.

```
                 │
                 ▼
     [원생별 db.attendance 검색]
                 │
        ┌────────┴────────┐
 ┌──────▼──────┐   ┌──────▼──────┐
 │ att 레코드  │   │ att 레코드  │
 │  존재 함    │   │  존재 안 함 │
 └──────┬──────┘   └──────┬──────┘
        │                 │
        ├─────────────────┼────────────────────────┐
        ▼                 ▼                        ▼
  [att.status에]     [현재일 = 오늘 이고]     [수업 미경과 또는]
  [기반하여 매핑]    [수업시간 + 20분 경과]   [현재일이 미래]
  - present: 출석         │                        │
  - late: 지각            ▼                        ▼
  - absent: 결석       (미확인)                 (수업 예정)
        │
        ▼
  [att.leavingTime]
  [유무 추가 확인]
  - 등원 기록은 있으나 
    하원 시간이 없고 
    운영 시간이 지남 
        │
        ▼
    (하원누락)
```

## 4. 인스펙터 드로어 실데이터화 매핑 설계

드로어 오픈 시 선택된 `studentId`를 통해 아래 요소를 동적으로 로드합니다.
1. **상단 프로필**: `getStudent(studentId)`의 데이터 바인딩 (성명, 악기명, 강사명).
2. **출결 요약 지표**: 최근 30일(또는 지정 기간) 동안 `getAttendanceForStudent(studentId)` 내역을 기반으로 완료 수업 수, 출석, 지각 횟수를 카운트하여 렌더링.
3. **최근 30일 출결 현황 (cal-mini)**: 
   - 30일간의 날짜에 대해 해당 요일 수업 예정 여부를 체크하고, `db.attendance`에 매칭되는 실제 레코드 상태(`present` | `late` | `absent`)에 맞춰 색상 클래스를 부여합니다.
   - `new Date().getDate()`를 획득하여 오늘 날짜 셀에 `.today` 하이라이팅을 줍니다.
4. **최근 전송 메시지**: `getMessagesForStudent(studentId)` 이력을 역순 정렬하여 수신 채널과 발송 성공/실패 여부를 목록에 주입합니다.
5. **수납 정보**: `db.payments`에서 이번 달 결제 예정 청구서 데이터를 확인하여 수납 여부에 따라 `미납` 및 `결제예정` 배지 처리를 노출합니다.

## 5. 예정 수업 횟수 비례형 출결 워닝 정책

### A. 기존 고정 횟수 기준의 한계
학생마다 주당 수업 횟수가 다릅니다. 주 1회 수강생이 최근 4주 내 3회 결석하는 것은 결석률 **75%**에 해당하는 매우 심각한 결석 상태이지만, 고정 횟수(최근 2주 3회 결석)로만 경고를 잡으면 주 1회 학생의 이상 징후를 감지할 수 없는 사각지대가 발생합니다. 따라서 고정 결석 횟수만으로 워닝하지 않고 **예정 수업 횟수 대비 비율**을 기준으로 판정하며, 절대 횟수는 보조 정보로만 사용합니다.

### B. 비율 기반 워닝 설계 공식
1. **예정 수업 모수 ($N$)**: 최근 28일(4주) 동안 원생이 정규 스케줄 및 오버라이드로 출석해야 했던 총 예정 수업 횟수.
2. **결석 및 미등원 횟수 ($A$)**: 출결 상태가 `absent` 또는 `미확인`인 일수.
3. **지각 횟수 ($L$)**: 출결 상태가 `late`인 일수.
4. **비출석률** = $\frac{A}{N} \times 100$
5. **지각률** = $\frac{L}{N} \times 100$
6. **출석률** = $\frac{N - A}{N} \times 100$

### C. 워닝 위험도 분류 기준 (MVP 기본값 초안)
* **비출석 위험 Red (상담 필요)**: 최근 4주 기준 비출석률 $\ge 30\%$ 인 경우.
  - *예시: 예정 8회 중 3회 비출석 시 (비출석률 37.5%로 즉시 빨간색 경고 추가)*
* **출석률 저조 Amber (관심 필요)**: 최근 4주 기준 출석률이 75% 미만인 경우.
* **지각 반복 Amber (태깅 지도)**: 최근 4주 기준 지각률 $\ge 25\%$ 인 경우.
* **긴급 Critical (즉시 조치)**: 
  - 비성인 원생이 최근 2회 연속 미등원/결석 상태인 경우.
  - 또는 오늘 수업 시작 후 설정값(예: 15분) 기준 지연 상태인데 출결이 여전히 '미확인' 상태인 경우.

> [!NOTE]
> **설정 조정 기능 확보 계획**
> 위 임계값 기준들은 MVP 기본값 초안이며, 추후 학원 설정(Settings) 메뉴를 통해 원장 개별 기준에 맞게 조정이 가능하도록 옵션을 확보할 예정입니다.
> 화면 문구는 반드시 `최근 4주 예정 N회 중 M회, X%` 형태로 전체 분모와 분자를 구체적으로 표시하여 학부모 상담용 데이터 설득력을 갖추게 합니다.

## 6. Phase 9C 구현 분할안

작업의 안정성과 검증 가능성을 보장하기 위해 다음과 같이 5가지 세부 마일스톤으로 구분하여 진행합니다.

* **Phase 9C-1**: 일자별 출결 rows 생성 및 날짜/상태/악기/강사/이름/회원번호 필터 실동작
  - `dailyClasses` 리스트 획득 방식을 `getTeacherStudentScheduleForDate(selectedDate)` 기반으로 실데이터화하고, 조회 날짜/상태/과목/강사/IME 보정 이름-회원번호 검색 필터를 연동합니다.
* **Phase 9C-2**: 원생별 / 악기·반별 / 강사별 조회 탭 실동작
  - 대시보드 내 조회 탭을 전환할 때 원생 단위 통계, 악기/반별 예정 및 실시간 등원 카드, 강사별 당일 배정 원생들을 실데이터로 온전히 표출합니다.
* **Phase 9C-3**: 인스펙터 드로어 실데이터화
  - 학생 클릭 시 노출되는 드로어 프로필, 최근 30일 통계 지표, 미니 캘린더 그리드, 실제 SMS/알림톡 발송 이력, Payments 미납 배지를 실데이터로 렌더링합니다.
* **Phase 9C-4**: 예정 대비 비율 기반 출결 워닝 selector 및 워닝 콘솔 연동
  - `stateStore`에 `getStudentAttendanceStats` API를 구현하고, 뷰단의 출결 워닝 카드가 비출석률 $\ge 30\%$, 지각률 $\ge 25\%$, 연속 2회 미등원 등의 비율 정책에 맞춰 동적으로 추출되도록 적용합니다.
* **Phase 9C-5**: 오늘 원장 콘솔 TodayTask 추천확인과 출결관제 처리 상태 연결
  - 출결관제 뷰에서 출결(출석, 지각, 결석)을 기록하면 `TodayTask` 내 `SYSTEM_RECOMMEND_ATTENDANCE_LATE` 추천 업무가 자동으로 동기화(done 처리)되도록 연계합니다.

## 7. 주요일정관리와의 연결 판단

* **현 단계 방침**: 지금 단계에서는 주요일정관리 페이지 구현으로 넘어가지 않고, **출결관제 실기능 완성**을 우선으로 완료합니다.
* **데이터 계약 제안 지점**: 출결관제 기능에서 학원 방학, 공휴일, 보강 일정, 상담 일정, 학원 전체 행사 등 "주요일정관리"의 정보들이 출결 판단에 직접 영향(스케줄 비우기, 보강 수업 추가, 상담 태스크 생성 등)을 주는 시점에 이르렀을 때 유기적인 데이터 계약(Event/API 정의)을 맺어 연동할 것입니다.

## 8. 추가 제안 / 다음 개선 후보

아래 항목은 실무 편의를 높이기 위한 좋은 UX 아이디어들이며, 9C의 기본 구현 범위를 흩뜨리지 않기 위해 설계에 반영하되 실제 구현은 승인 이후 단계적으로 진행합니다.

### 1. 실시간 미등원 토스트/알림
* **필요성**: 원장이 출결관제 페이지에 머물고 있지 않을 때도, 수업 시작 15분이 경과한 미등원 학생을 인지해야 합니다.
* **기대효과**: 지연 발생 즉시 브라우저 우측 하단이나 헤더 벨 아이콘을 통해 실시간 알림을 주어 즉각적인 대처가 가능해집니다.
* **지금 구현하지 않는 이유**: 9C에서는 관제 화면의 데이터 결합 정밀도와 비율 워닝 계산식 검증에 집중하고, 백그라운드 폴링 및 전역 알림 토스트 구조는 9C 범위 이후의 알림 엔진 개발 시 결합하는 것이 구조상 안전합니다.

### 2. 보호자 SMS/알림톡 템플릿 발송
* **필요성**: 미등원, 결석, 혹은 수납 미납이 식별된 학생에게 즉각적으로 공지해야 할 상황이 잦습니다.
* **기대효과**: 인스펙터 드로어 내에 `안내톡 즉시 발송` 버튼을 제공하여, 별도의 메시징 메뉴로 이동하지 않고도 템플릿화된 문자를 원클릭 전송할 수 있습니다.
* **지금 구현하지 않는 이유**: 현재 Phase 9C에서는 실제 외부 연동 발송(SMS/알림톡 API)을 모의로만 다루고 실제 쓰기 동작은 막아두라는 정책이므로, 조회 데이터 정합성 완성 후에 추가 진행합니다.

### 3. 30일 출결현황 연도/월 헤더
* **필요성**: 인스펙터 드로어 내 미니 캘린더 그리드(`cal-mini`)가 30일간의 데이터를 나열하고 있으나, 정확히 몇 월 며칠의 데이터인지 시각적으로 월 경계 구분이 모호합니다.
* **기대효과**: 그리드 상단에 월 단위 캡션이나 월 분리 라인을 추가하여 타임라인 가독성을 확보합니다.
* **지금 구현하지 않는 이유**: MVP 구조의 미니 캘린더 컴포넌트 마크업을 단순하게 유지하여 로직 테스트 검증에 우선순위를 두기 위함입니다.

### 4. 30일 미니맵 날짜별 사유 툴팁
* **필요성**: 미니 캘린더 셀에 결석/지각이 표시되어 있을 때, 해당 날짜의 결석 사유(note)가 무엇인지 바로 확인하고 싶습니다.
* **기대효과**: 각 날짜 셀에 마우스 오버(Hover) 시 말풍선 형태로 사유(`att.note`)를 즉시 띄워 편의성을 극대화합니다.
* **지금 구현하지 않는 이유**: 마우스 오버 포커스 툴팁 UI 제어를 추가하면 스타일 시트 및 모바일 터치 대응 등 UI 연출 부하가 늘어나므로 기본 탭/드로어 동작 검증 이후 연동합니다.

### 5. 인스펙터 내 수납 즉시 처리 액션
* **필요성**: 드로어에서 미납 수강료가 확인되었을 때, 학부모가 현금이나 수동 카드로 현장 결제하여 원장이 즉시 '완납'으로 변경 처리해야 하는 현장 시나리오가 있습니다.
* **기대효과**: 미납 배지 옆에 `수납 완료 처리` 단축 버튼을 제공해 결제 상태를 즉각 영속화합니다.
* **지금 구현하지 않는 이유**: 수납 상태의 '쓰기/변경'은 수납 결제 관리 페이지(`billing.js`)의 비즈니스 로직과 깊게 엮여 있으므로, 수납 도메인 기능의 안전한 결합을 위해 9C의 단순 조회 범위에서 제외합니다.
