# Phase 9A: 출결관제 및 주요일정관리 실제 구현 전 매핑/정책 설계서

본 문서는 대화 및 기획 산출물을 바탕으로 **출결관제** 및 **주요일정관리** 페이지를 DayDay 서비스에 정식 구현하기 전, 기존 데이터 모델, 상태 관리, 라우팅, 그리고 멀티 테넌트 SaaS(Segment-First) 아키텍처와 어떻게 정합성 있게 매핑하고 연동할지 정의하는 설계 문서입니다.

---

## 1. 두 페이지의 목적 정의

기존의 단순 기록용 테이블에서 벗어나, 원장의 행정 피로도를 최소화하고 실질적인 운영 리스크를 예방하는 것을 본질로 삼습니다.

### 1) 출결관제 (Attendance Control Console)
* **정의**: 단순 "누가 등원했는지"를 기록하는 수동 출석부가 아닌, **실시간 리스크 탐지 및 보호자 커뮤니케이션(알림) 관제 센터**입니다.
* **핵심 가치**:
  * 바쁜 원장이 100명이 넘는 원생 목록을 하나하나 훑어볼 필요가 없도록, 정상 등원자는 하단으로 숨기거나 접습니다.
  * **미등원(안전 리스크)**, **하원누락(행정 리스크)**, **메시지 발송 실패(민원 리스크)**, **반복 결석(이탈 리스크)** 등 즉각적인 조치가 필요한 예외 대상(Action Queue)을 최상단에 강제 노출하고, 해당 행에서 즉각적인 액션(전화, 알림톡 재발송, 수강 차감 판단 등)을 1-Click으로 실행하게 돕습니다.

### 2) 주요일정관리 (Major Milestones & Student Console)
* **정의**: 일정의 단순 나열(달력 표기)이 아닌, **일정 마일스톤과 이에 연계된 참여 원생별 행정 상태 및 공개 범위를 관리하는 경영 도구**입니다.
* **핵심 가치**:
  * 콩쿠르, 입시 실기, 보강 레슨, 학부모 상담, 정기 음악회 등 핵심 일정별로 참여할 원생들을 일괄/개별로 매핑합니다.
  * 일정별 원생 준비 상태(예: 콩쿠르 참가 곡명, 보강 가능 시간대 확인, 리허설 여부 등)와 **학부모 앱 공개 상태 제어(예정, 확인필요, 완료, 보류, 공개됨)**를 통합적으로 통제하여 행정 혼선을 방지하고 학원 서비스의 격을 높입니다.

## 2. 구현 우선순위 및 위험도 분석

### 1) 1순위: 출결관제 (Attendance Control)
* **이유**:
  * **민원 및 안전의 즉각성**: 비성인 원생의 등하원 여부는 학부모 안심(안전)과 즉각 직결되며, 알림톡 미발송/실패는 당일 학부모 민원으로 번집니다.
  * **TodayTask와의 시너지**: 미등원 20분 경과 룰, 출결 입력 지연 룰 등 '오늘 원장 콘솔'의 추천 엔진과 실시간으로 연동되어 원장이 당장 가치를 느낄 수 있는 메인 루프입니다.
* **위험도 및 주의점**:
  * **트래픽 및 성능 부하**: 등하원 시간대에 100명 이상의 키오스크 태그/출결 데이터가 집중적으로 유입되므로, 실시간 UI 갱신 및 DB 쓰기 병목이 발생할 수 있습니다.
  * **메시지 발송 비용 및 피로도**: 자동 알림톡 오발송 또는 중복 발송 시 학부모의 피로감이 극대화되므로 정교한 중복 방지 디바운싱(Debouncing) 장치가 필수적입니다.

### 2) 2순위: 주요일정관리 (Major Milestones)
* **이유**:
  * 입시, 콩쿠르, 보강 등은 중장기 원생 관리와 이탈 방지에 필수적이지만, 일일 출결 사고에 비해 긴급도(Real-Time)가 상대적으로 낮습니다. 출결 관제 모듈을 먼저 안착시킨 뒤 순차 구현하는 것이 제품 안정성 측면에서 우수합니다.
* **위험도 및 주의점**:
  * **스케줄 정합성 복잡도**: 원생 개별 정규 수업 시간표(sessions)와 주요일정(행사/보강) 간의 충돌 여부를 감지하고 대강/보강 일정을 유연하게 편성해야 하므로 데이터 매핑 연산이 복잡해질 수 있습니다.

## 3. 출결관제 세부 정책 설계

### 1) 출결 상태 정의
* **예정 (Scheduled)**: 당일 수업 배정이 존재하고, 아직 수업 시작 예정 시간이 오지 않음.
* **출석 (Present)**: 수업 시작 전후로 정상 등원 태깅을 완료함.
* **지각 (Late)**: 수업 시작 시간 기준 설정값(예: 10분) 초과 후 등원 태깅을 완료함.
* **결석 (Absent)**: 수업이 종료되었거나 원장이 사전에 결석으로 확정한 상태.
* **미확인 (Pending/Overdue)**: 예정 시간이 경과(예: 20분 초과)했으나 아직 출결 태깅 또는 원장의 처리가 없는 상태. (관제 최우선순위)
* **하원 누락 (Checkout Missing)**: 등원 기록은 정상적으로 존재하나, 수업 종료 예정 시간 + 30분이 지나도록 하원 태깅이 없는 상태.

### 2) 미등원 / 지각 / 하원누락 자동 판정 기준
* **미등원 경보**: `수업 시작 예정 시간 + 20분`이 지나도록 출결 상태가 `Scheduled` 상태로 남아 있을 경우 자동으로 `Pending(미확인)` 상태로 전환하고 경고 카드를 띄웁니다.
* **지각 판정**: `수업 시작 예정 시간 + 10분` 이후에 등원 키패드 태그가 감지되면 자동으로 `Late(지각)`로 기록합니다.
* **하원누락 경보**: 등원 시각은 존재하나 `수업 종료 시간 + 30분`이 경과하도록 하원 기록이 없을 때 자동으로 하원누락 경보를 발동합니다.

### 3) 성인 / 비성인 구분 알림 정책
* **비성인 원생 (기본 안심형)**:
  * 등원 및 하원 태깅 시 **보호자에게 실시간 알림톡이 자동으로 즉각 발송**됩니다 (기본값 ON).
  * 미등원 20분 초과 시, 원장 콘솔에 `[미등원 보호자 알림]` 승인형 액션 버튼을 띄워 원장 확인 후 수동/승인형으로 발송합니다.
* **성인 원생 (티켓/회차 차감형)**:
  * 등하원 실시간 알림톡 발송은 기본적으로 꺼져 있습니다 (기본값 OFF).
  * 출결은 주로 **수강권 차감 및 차감 보류(보강 필요) 판정**을 위해 활용됩니다. 지각/결석 시 수강 회차 차감 여부 룰을 원장에게 질문 형식으로 콘솔에 제공합니다.

### 4) 메시지 발송 / 실패 / 재시도 및 피로도 관리
* **채널 라우팅 및 대체 발송**:
  * 카카오 알림톡(또는 앱 푸시) 발송을 우선 시도하며, 통신사 일시 장애 또는 차단 등으로 전송 실패(Failed) 응답이 올 경우 **일반 SMS로 자동으로 대체 발송(Fallback)**을 트리거합니다.
* **중복 발송 차단**: 동일 원생에 대해 등/하원 신호가 통신 노이즈 등으로 10분 이내에 중복 입력되는 경우, 최초 1회 발송만 허용하고 2회째는 발송을 자동 차단합니다.
* **피로도 상한제**: 동일 보호자 수신처 기준으로 하루 자동 알림 발송은 최대 3건으로 제한하며, 이를 초과할 예정 시 4번째 알림부터는 묶음 요약 메시지로 수동 발송을 유도합니다.

### 5) 출결 워닝(Warning) 판정 기준
* **반복 결석 (중간 심각도)**: 최근 4주 이내에 주 2회 이상 결석하거나 누적 3회 이상 결석 시 워닝을 발동하고 상담 추천 목록으로 올립니다.
* **출석률 하락 (중간 심각도)**: 당월 누적 출석률이 80% 미만으로 내려가거나, 전월 출석률 대비 10% 이상 하락 시 이탈 위험 상태로 판정합니다.
* **지각 누적 (낮은 심각도)**: 당월 누적 지각 3회 이상 시 경고를 띄워 성인 타임 차감 검토 및 비성인 대상 생활 지도를 유도합니다.
* **하원 누락 & 메시지 실패 (높은 심각도)**: 안전과 민원에 즉각적인 타격을 주므로 판정 즉시 최상위 적색 경고로 콘솔에 노출합니다.

### 6) 오늘 원장 콘솔 (TodayTask) 추천확인 연동 방식
* 출결관제 모듈에서 자동 판정된 **미등원(20분 초과), 하원 누락, 메시지 전송 실패** 건은 백그라운드 엔진에 의해 `TodayTask` 상에 `status: 'open'`, `category: '확인필요'`(또는 `추천확인`) 형태의 태스크 카드로 실시간 생성됩니다.
* 원장이 오늘 원장 콘솔에서 해당 추천 카드를 확인하거나 [확인/이동] 버튼을 누르면 출결관제 페이지의 해당 원생 행으로 즉시 포커스되며 드로어(Drawer)가 열립니다.
* 출결관제 화면에서 사유를 입력하거나 알림 재발송을 마치는 순간, 해당 `TodayTask` 카드는 자동으로 `status: 'done'`으로 동기화되어 해결 처리(Auto-Resolve)됩니다.

## 4. 출결관제 화면 UI/UX 구조

전체 원생 리스트를 스크롤하는 기존의 비효율성을 극복하고 **행정 처리 대기열**로 기능하도록 화면을 재구조화합니다.

```
+---------------------------------------------------------------------------------+
|  [ 출결 관제 요약 콘솔 ]                                                       |
|  조회: 오늘 (2026.06.07)  |  수업일수: 12일  |  출석률: 92.4% (성인 88% / 비성인 95%)  |
|  출석/결석: 88건 / 4건    |  지각: 3회 (전주대비 -1) | 메시지실패: 2건 (적색 경보)     |
+---------------------------------------------------------------------------------+
|  [! 오늘 원장 액션 큐 - 미처리 대기열 4건]                                      |
|  - [메시지 실패] 김민준 (보호자1) -> [연락처 확인 및 재발송]                     |
|  - [미등원 경보] 이서연 (15:00 수업, 25분 경과) -> [보호자 안심톡 전송]          |
|  - [하원 누락] 박지후 (16:30 종료, 40분 경과) -> [하원 확인 처리]                |
+---------------------------------------------------------------------------------+
|  [출결 목록 상세 테이블]  [조회모드: 일자별 / 원생별 / 반·악기별 / 강사별]       |
|  필터: 전체 악기 | 전체 강사 | [v] 예정/정상 출석자 숨기기                       |
|                                                                                 |
|  시간    원생명   반/악기    담당강사   출결상태   등원시각   메시지 상태   액션   |
|  -----------------------------------------------------------------------------  |
|  15:00  김민준   피아노중급  정은지     미확인     -          실패(재시도) [재발송]|
|  15:30  이서연   바이올린    이현우     예정       -          예약대기     [결석확정]|
|  [+] 정상 출결 완료자 (32명 접혀있음 - 클릭 시 펼침)                            |
+---------------------------------------------------------------------------------+
```

### 1) 주요 레이아웃 설계 정책
* **예외 중심 노출**: 정상 출석자는 디폴트로 아코디언 컴포넌트 내에 접어서 숨깁니다. 화면 로딩 시 오직 미확인, 지각, 하원누락, 결석 등 **액션이 필요한 예외 데이터만 즉시 노출**됩니다.
* **조회 모드 전환**:
  1. **일자별 모드**: 오늘 하루의 출결 상태를 시간 흐름 순으로 대응하며 일일 행정을 종결하는 모드입니다.
  2. **원생별 모드**: 특정 원생의 최근 4주/3개월 출결 캘린더 그리드와 출결 누적 통계를 리포트하고, 보호자 상담 이력과 결합하는 화면입니다.
  3. **반·악기별 모드**: 클래스 단위 출결 하락 현상을 분석하고 요일/시간대별 출결 저해 요인을 탐지하기 위한 랭킹 대시보드입니다.
  4. **강사별 모드**: 강사 담당 원생들의 출결 처리율 및 미처리 방치 현황을 검토하기 위한 화면입니다.
* **행 클릭 시 상세 드로어(Drawer) 오픈**: 테이블의 특정 행을 클릭하면 우측에서 즉시 상세 드로어가 슬라이드 인하여 해당 원생의 학부모 연락 정보, 최근 4주 출결 이력, 수납 미납 디테일, 오늘 사유 입력 폼을 한눈에 보여줍니다.

## 5. 주요일정관리 세부 정책 설계

### 1) 일정 유형 정의
* **행사 (Event)**: 정기 음악회, 캠프, 오픈 클래스 등 학원 전체 혹은 대규모 참여 일정.
* **입시 (Admission)**: 실기 고사, 모의 테스트, 입시 설명회 등 수험생 중심의 고강도 밀착 관리 일정.
* **보강 (Makeup)**: 결석 원생 구제를 위해 정규 수업 외에 특별 편성된 일대일 또는 그룹 레슨 일정.
* **상담 (Consulting)**: 학부모 대면/전화 상담, 이탈 방지 정기 면담 등 행정 일정.
* **교재/준비물 (Material)**: 교재 마스터 배포일, 교재비 일괄 청구 및 교환 확인일.
* **기타 (Others)**: 강사 워크숍, 학원 정기 휴무일 등.

### 2) 공개 상태 라이프사이클
* **예정 (Draft/Scheduled)**: 내부적으로 일정이 기획 및 등록되었으나, 학부모 및 원생에게 노출되지 않는 비공개 상태.
* **확인필요 (Pending Review)**: 일정이 조율 중이거나 참여 학생 확정이 완료되지 않아 최종 검토가 필요한 상태.
* **공개됨 (Published)**: 학부모용 앱 및 알림톡을 통해 일정이 정식으로 배포되어 사용자 화면에 노출되는 상태.
* **완료 (Completed)**: 보강, 입시, 상담 등의 일정이 정상적으로 진행 완료되어 행정이 마감된 상태.
* **보류 (Deferred)**: 일정이 일시 중단되거나 연기된 상태.

### 3) 일정 추가 및 참여 원생 매핑 UX
* **입력 부담 최소화**: 일정 등록 시 필수값은 **[제목], [날짜], [일정 분류], [참여 대상]** 4가지만 둡니다. 세부 곡명, 참가 부문, 준비물 등은 메타성 메모 필드로 분리하여 나중에 기입하도록 유도합니다.
* **일괄 매핑 기법**: 참여 대상을 지정할 때, 원생 한 명 한 명 검색하여 추가하는 방식 외에 **[특정 강사 담당생 전체], [피아노 전공반 전체], [토요일 수업자 전체]** 등의 필터링을 통해 원생들을 대량으로 일괄 매핑하는 기능을 제공합니다.

### 4) 다가오는 수업 및 일정 정합성 연동
* 주요일정(보강, 입시)을 특정 타임슬롯에 지정할 때, **정규 수업 배정 데이터(sessions)**와 실시간 비교 연산을 수행합니다.
* 해당 시간에 원생의 정규 수업이 중복 배정되어 있다면 자동으로 `[정규 수업과 충돌 위험]` 안내 표시를 제공하고, 보강 일정으로 대체할 것인지(대강/보강 처리) 결정하는 분기 정책을 수립합니다.

## 7. Segment-First Architecture 관점의 격리 설계

DayDay 서비스는 장기적으로 음악학원뿐 아니라 PT/필라테스 헬스장, 개인 레슨, 소규모 매장 등 타 업종으로의 확장이 용이하도록 코어 엔진과 업종 도메인을 분리합니다.

### 1) Core Engine (공통 비즈니스 엔진)
* **Attendance Engine**: 등하원 상태 값의 상태 전이 머신, 메시지 대체 발송(Fallback) 대기열 큐, 그리고 시간대별 지연 감지 타이머 로직은 업종과 무관하게 재사용되는 공통 코어로 격리합니다.
* **Milestone Engine**: 주요일정을 등록하고 대상자(회원)를 매핑하며, 다가오는 스케줄과의 충돌을 탐지하는 내부 이벤트 버스는 공통 구조로 유지합니다.

### 2) Domain Adapter (업종별 연동 계층)
* **academy_adapter**: 음악학원의 특화 속성(원생, 담당강사, 정규 매칭 레슨, 악기/반)을 공통 코어의 `membershipId`, `staffId`, `assignedSession` 형태로 포맷 변환하여 연동해 줍니다.
* **pt_pilates_adapter**: 헬스장의 속성(회원, 배정 트레이너, 회원권 PT 세션, 락커 번호)을 공통 코어로 매핑하여 동일한 출결관제 큐와 일정 큐에서 작동할 수 있게 돕습니다.

### 3) Terminology Layer (용어 치환 사전을 통한 UI Shell 재사용)
* 뷰 컴포넌트는 단어명이나 뱃지 텍스트를 하드코딩하지 않고, 활성화된 세그먼트의 설정(`Segment Config`)에 정의된 사전을 거쳐 렌더링합니다.

| 공통 내부 변수 | 음악학원 세그먼트 표기 | PT / 필라테스 세그먼트 표기 | 개인 레슨 세그먼트 표기 |
| :--- | :--- | :--- | :--- |
| **Member** | 원생 | 회원 | 학생 |
| **Staff** | 강사 | 트레이너 | 선생님 / 튜터 |
| **Session** | 레슨 / 수업 | 세션 / PT 예약 | 과외 수업 |
| **Grouping** | 반 / 악기 | 이용권 / 락커 | 과목 |
| **Action** | 등원 / 하원 | 체크인 / 퇴장 | 수업 개시 / 종료 |
